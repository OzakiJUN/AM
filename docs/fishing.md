# 星屿鱼塘

2026-11-02。内置多人钓鱼游戏，在工坊「小游戏 → 星屿鱼塘」或频道顶栏的手柄菜单开局。当前工坊的下载包只支持数据作品，不支持服务端经济、数据库和可执行组件，所以这次按 Weiqi 的备选方案内置。没有扩大工坊执行权限，不需要下载包或签名私钥。客户端、服务器都要升级。

## 鱼塘

- 一个方形鱼塘 12 个座位，不限时。创建者自动坐下，任何会话成员可以点空座入座，不需要审批。坐下、换座、收获后都会自动抛竿。空位选择是实体座位号 1–12。
- 每竿默认在 10–3600 秒（60 分钟）之间等概率随机抽取一个整数秒，包含两端；疾风竿按品质缩短，但不低于配置的最短等待（默认 10 秒）。已有抛竿不重抽，新抛竿使用当前规则。水面起涟漪后有 30 秒手动收杆窗口，窗口结束会托管收杆。右边「收杆」，或点别人的座位再「用手套偷鱼」。鱼种、尺寸和奖励都由服务器抽取，客户端不提交这些结果。
- 鱼塘采用紧凑水岸布局：12 座在塘边分布，上钩浮漂与座位一起高亮；上钩前不显示倒计时或预计等待，只显示水面与浮漂；上钩后右边显示收杆窗口倒计时、独立收杆区、两个装备位与对应冷却，短窗口和手机宽度下可滚动操作。
- 商店、图鉴、卡包结果只改变自己的 UI。金币和自己装备的工具随处可见。关闭窗口不等于离座，可用「离座」释放位置，房主可以「关闭鱼塘」。
- 同一份存档同时只在一台服务器挂机，多设备共享钱包、鱼篓和冷却。切换到另一服务器开始游戏或交易时，由客户端完成存档迁移，旧服停止产出，新服接续。当前登录的本人账号参照现有资料同步关系共用存档，不按昵称猜测其他人的身份。
- 服务端每秒独立推进鱼塘，客户端完全关掉也会自动收杆、自动寻找偷鱼机会、自动防偷。普通竿在窗口结束时托管收杆，机械竿冷却就绪可在上钩时立即收，缩短别人能偷的时间。服务器重启后按持久时间线追补未结算事件，按时间先后结算，不依赖客户端读取。补结算期间暂停迁移和离座，避免尚未领取的积压收益被丢掉。每事务最多 256 个事件，积压会在下一轮继续，不重复发奖励。鱼篓满仍会放生，不自动卖。
- 普通竿免费自带。背包满时鱼被放生，有提示。默认鱼篓 1000 条、未开卡包 1000 包。鱼塘使用现有每会话同时游戏数量限制 `limits.max_games_per_conv`。

## 100 种幻想鱼与长度

图鉴配置是 [`server/internal/game/fishing_rules.json`](../server/internal/game/fishing_rules.json)，含 100 个唯一 ID、名称、平均长度、基础价值、稀有度、矢量外形、花纹和说明。客户端直接读取服务端图鉴绘制图像，不连外部素材网站。同一个 ID 在卡面和鱼获中对应同一种鱼。

| 鱼种稀有度 | 常见 | 奇异 | 稀有 | 史诗 | 传说 |
| --- | --- | --- | --- | --- | --- |
| 种数 | 20 | 20 | 20 | 20 | 20 |
| 默认权重 | 55 | 25 | 12 | 6 | 2 |

先抽鱼种档位，再等概率抽该档一条鱼。长度直接从连续对数正态分布抽取，标准差参数 `length_sigma` 默认 0.22，`实际长度 = 平均长度 × exp(σZ − σ²/2)`，Z 是标准正态随机数。以米为单位，四舍五入到 0.01 米、最低 0.01 米；没有五档尺寸定价。比如标准 50.00 m 的鱼可以是 53.16 m，也可以是 53.17 m。

鱼价依据这条鱼的实际长度计算：`基础价值 × [1 + length_value_scale × log(实际长度/平均长度)²] × 点金竿倍率`，默认 scale=8。长、短两个方向越极端都越珍贵，同一旧尺寸档里的不同长度也会计入价格。最终价格四舍五入到分。

金币、基础价格和鱼获价格使用整数分保存和加减，通过 JSON 输出两位小数金币，避免浮点余额累积误差。后来换装备不改变已经钓到的鱼的价值。每种鱼仍保留自己的最短/最长历史纪录，但已出售的鱼不能通过纪录继续挂上主页。偷来的鱼能出售，不能作为自己钓到的鱼展示。

每次收获默认 93% 是鱼、4% 钱袋、2.5% 单张卡、0.5% 卡包。钱袋默认 15–85 币，包含两端。满卡包时卡包掉落改抽鱼。鱼篓满时放生鱼，不自动卖。

## 商店与工具

卖鱼需要明确选择鱼获 ID，服务端检查全都属于自己的鱼篓，重复 ID 拒绝。每条鱼按捕获时已经确定的价值卖出，后来换装备不会改价。

五种工具各有五档品质，价格为 120/450/1500/5000/16000 币，购买更高档替换当前品质，按该档全价购买、不返还旧款。可以直接买高档。最多同时装备两类，同类一件。卸下、换品质、跨频道都不清冷却。

| 工具 | 五档效果 |
| --- | --- |
| 疾风钓竿 `speed` | 等待缩短 12/22/32/42/55% |
| 机械钓竿 `auto` | 自动收杆一次，冷却 150/120/90/65/40 秒 |
| 点金钓竿 `value` | 鱼获价值提高 15/30/55/90/150% |
| 幻影手套 `glove` | 偷钩上收获成功率 35/48/62/78/95%，冷却 120/85/55/35/20 秒 |
| 守鱼结界 `ward` | 基础防御率 80/85/90/95/97%，冷却 240/200/160/120/90 秒 |

手套可以手动使用，也会由服务端在目标上钩 2.5 秒后、本人手套冷却就绪时自动尝试。只针对本鱼塘别的已上钩、尚未收杆的座位。成功率 35/48/62/78/95%，破盾修正 0/5/12/22/35 个百分点。结界就绪时先判定防御，实际挡住概率 = 结界防御率 − 手套破盾修正；不论成功挡住与否，结界进入冷却。手套失败也消耗自己的冷却。成功者拿走这一钩收获，原玩家重新抛竿。

满级手套冷却 20 秒、破盾修正 35 点，满级结界冷却 90 秒。即使满级结界就绪，对满级手套也只挡 62%，然后手套仍有 95% 的取获成功率，因此满级手套强于满级结界，结界仍能减轻损失。钱袋、单卡和卡包在收杆前不揭晓，也可能被偷走。

机械竿每次冷却自动收一次；未冷却就绪的窗口仍会在结束时由普通托管收杆，不停止离线挂机。全部结算使用服务器时间，客户端不提交奖励、命中结果或时间。

## 客户端跨服存档

Weiqi 选择客户端同步，不依赖固定的主存档服务器。客户端中已经登录的本人主账号会共用一个全局存档 identity。每个服务器上的账号另有不可迁移的随机 local_slot，鱼获使用全局随机 ID 和 owner_key，跨服后组件不需要重新匹配本地 user_id。

- 最后实际游戏/交易的服务器是当前产出服，其余服保存只读镜像，不会同时挂机产出，也不会把金币和卡片副本相加。后台每 15 秒和操作完成后同步在线副本。客户端关闭时当前产出服继续挂机，其余服暂时显示上次同步的收藏。
- 迁移先在来源服按 revision 原子冻结，记录 transfer_id 和目标 local_slot，再由客户端带着快照与交易去重账本激活目标。激活重试返回同一次结果，不能在别的目标账号复用；旧版本镜像也不能覆盖活动副本。旧服座位由服务端清理。
- 客户端持久保存未完成迁移的来源/目标和编号，完整快照可从冻结来源重新读取；不会把大量交易账本塞进 localStorage。激活响应丢失可恢复，不会多扣钱或另开一份产出存档。
- 原产出服离线时，可查看已同步副本；需要等原服连上，才能把还在那边运行的存档迁移到另一服。客户端不在线时不做跨服同步。跨设备使用同一组已登录服务器，可从当前活动副本恢复关系。
- 非空的独立旧存档不自动合并或覆盖，遇到版本/身份冲突保留数据并拒绝迁移。AI 是独立的游戏账号，不把各个不同 AI 的财产混进人的存档；没有指定“同一个 AI”的跨服身份关联时，也不按 AI 昵称合并。

这是客户端中转存档，不是服务器间的可信经济联邦。接收端会校验结构、版本、目标绑定与容量，但不能证明客户端或外服管理员没有改过自己导入的数据。日常防重复和冲突保护不等于跨服防作弊认证。

## 鱼卡与徽章

- 每包 180 币，四张独立抽取。卡片鱼种等概率抽 100 种之一。
- 卡片档位铁、铜、银、金、镭射，默认权重 60/25/10/4/1，共 500 种组合。重复卡保留数量，不增加唯一收集进度。开包和单卡掉落都更新进度。
- 每档拥有不同鱼卡 25/50/75/100 种，自动获得该档 I/II/III/IV 级徽章，低级也保留。徽章用对应金属色的六边形星章和绶带，卡面镭射使用渐变光泽。没有卡片交易或销毁机制。

## 主页三个组件

仅用户主页可用，服务器主页不支持。展示端只读服务器保存的当前仍持有的本人鱼获、已拥有的卡和徽章，不信任组件配置里的金币、长度和卡数量。

| kind | 配置 | 容量 |
| --- | --- | --- |
| `fishing_fish` | `ids` 选择仍持有的本人鱼获 ID（十进制字符串） | floor(宽×高 / 2)，横宽竖放、纵长横放。可选择鱼篓里仍持有的本人钓获，卖掉后不再展示 |
| `fishing_cards` | `mode: cards` 与 `ids`（`0:f001` 等），或 `mode: progress` | 每格一张，进度模式显示五档各 /100 |
| `fishing_badges` | `{}` | 全部已解锁的徽章，超出区域可滚动 |

公开展示将已保存主页选择的个体 ID 与当前鱼篓逐条核对，必须仍持有且原捕获账号是本人。卖掉后接口立即不再提供该鱼，旧配置和历史纪录均不能恢复它，未选择的鱼篓个体不会公开。同一客户端成交后立即刷新组件，其他正在查看的客户端每 10 秒刷新本服收藏；跨服副本在客户端同步之后更新。鼠标悬停在鱼上可看名称、稀有度、标准与实际长度、偏差、价值和钓获时间。

编辑器提供收藏选择器，缩小组件时截取能展示的数量。服务端检查数量不能超过格数。公开展示接口不会输出钱包、私有鱼篓、装备、冷却和当前鱼塘。

## AI

`list_games`、`open_game(kind=fishing)`、`join_game`、`leave_game` 只走游戏接口，不会触发 `draw_picture` 或 NovelAI。`fishing_state` 给 AI 完整规则、100 鱼图鉴、服务端平衡参数和自己的账号。`fishing_act` 支持 `sit/reel/steal`，`fishing_shop` 支持卖鱼、购置和装备工具、买包开包。座位号对模型从 1 开始。AI 按主人原有游戏参与设置决定是否加入，入座后用同样接口关注上钩并收杆，不为每条鱼调用一次模型，也不在频道逐条报鱼获。AI 运行期间默认每 60 分钟整理一次自己的钓鱼组件，可在 AI 设置的桌游区域调整间隔，0 关闭。优先展示本人仍持有的高价值鱼和高档鱼卡，也补上已解锁徽章；卖出的鱼会移除。已有非钓鱼内容、位置和横竖屏布局保留，没有位置时跳过新增，不删东西腾位置。工具权限仍属于现有 `games` 分类。

## 接口和数据

协议先在 `api.proto` 中定义 `FishingData{state_json}` 与 `FishingActionRequest`，生成 Go/TS。JSON 版本 2。旧版钓鱼存档会在首次读取时持久补全全局身份，把厘米长度转为米，原金币面值保留，重复读取不会重新生成身份。

结构与服务端 `FishingAccount`、`FishingRules`、`Pond` 一致，所有用户、鱼获和鱼塘的 int64 标识在 JSON 中使用字符串，鱼获 ID 为全局随机十六进制字符串，避免 JavaScript 丢失精度。

- `GET /api/v1/fishing/rules` → `FishingData`，图鉴及当前平衡配置。
- `GET /api/v1/fishing/me` → `FishingData`，只返回当前认证账号。
- `POST /api/v1/fishing/me` ← `FishingActionRequest{action,item,quality,fish_ids,request_id}` → `FishingData`。动作 sell / buy_tool / equip / unequip / buy_pack / open_pack。请求编号 8–64 字符。每个新操作新编号，网络失败重试原编号。同一存档的编号在迁移时携带去重账本，重复操作仍去重，换参数重用报 `bad_request`。客户端在当前游戏窗口保留待重试编号，成功后清除。
- `POST /api/v1/fishing/sync` ← `FishingSyncRequest{mode,state_json,expected_revision,transfer_id,destination}` → `FishingData`，32 MiB 上限。mode=export 原子冻结，destination 是目标账号 local_slot；mirror 导入只读副本；activate 使用同一目标绑定接续产出。state_json 是 `{account,receipts}`，账号含 identity/local_slot/revision/frozen/transfer_id/transfer_to，receipts 是 request_id→fingerprint。迁移期间沿用 `game_state` 表示版本、活动副本或独立存档冲突。
- `GET /api/v1/users/{id}/fishing-showcase` → `FishingData{records,cards,badges}`，要求登录，不返回私有钱包。
- 现有 `/conversations/{id}/games` 的 kind 加 `fishing`。`Game.state_json` 加 `pond{seats[12],now}`，空座 `user_id="0"`，非空有 `bite_at/expires_at` 毫秒时间。`/games/{id}/act` 的 action 加 `sit`（target 空座 0–11）/ `reel` / `steal`（target 0–11）。普通 `join/leave/end` 复用现有路由。没有桌游式 start 和 rematch，重开需新开鱼塘。
- 未授权沿用 `not_member/no_permission`，不合法经济操作或未上钩沿用 `game_bad_move`，同账号已在别处钓鱼沿用 `game_state`，满座 `game_full`。不存在的展示用户沿用 `not_found`。

数据库迁移 `0023_fishing.sql` 在 SQLite/PostgreSQL 各新增 `fishing_accounts`（每账号一份 JSON）、`fishing_actions`（请求去重账本）。鱼塘依然存在现有 `games` JSON 行。交易锁账号，鱼塘动作先锁局再按账号 ID 升序锁涉及的账号，同事务保存收获、钱包和鱼塘，防止两个客户端同时领、卖、偷。卖鱼会影响主页的持有状态，玩家需要在保留展示与出售换币之间选择。SQL 仅在 store 包。

## 平衡配置

默认所有平衡参数及图鉴都在内嵌 `fishing_rules.json`。想调整时把完整 JSON 复制到服务器目录，比如 `data/fishing-rules.json`，在 `config.toml` 的 `[fishing] rules_file = "data/fishing-rules.json"` 指向它，重启生效。空字符串使用内置数据。禁止缺档、空分布、超界数字和重复鱼种，配置无效拒绝启动。分布中某项写 0 可关闭该掉落，整体权重必须为正。

上线后不要改变鱼的 ID，也不要删除旧 ID，卡和纪录以此保存。调整平均长度与基础价值只影响新鱼获，已有鱼获价值不变。
