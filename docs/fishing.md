# 星屿鱼塘

2026-11-02。内置多人钓鱼游戏，在工坊「小游戏 → 星屿鱼塘」或频道顶栏的手柄菜单开局。当前工坊的下载包只支持数据作品，不支持服务端经济、数据库和可执行组件，所以这次按 Weiqi 的备选方案内置。没有扩大工坊执行权限，不需要下载包或签名私钥。客户端、服务器都要升级。

## 鱼塘

- 一个方形鱼塘 12 个座位，不限时。创建者自动坐下，任何会话成员可以点空座入座，不需要审批。坐下、换座、收获或鱼游走后都会自动抛竿。空位选择是实体座位号 1–12。
- 默认等待 18–42 秒，水面起涟漪后有 30 秒收杆。右边「收杆」，或点别人的座位再「用手套偷鱼」。鱼种、尺寸和奖励都由服务器抽取，客户端不提交这些结果。
- 商店、图鉴、卡包结果只改变自己的 UI。金币和自己装备的工具随处可见。关闭窗口不等于离座，可用「离座」释放位置，房主可以「关闭鱼塘」。
- 同一账号同时只能坐一个鱼塘，多个设备共享钱包、鱼篓和冷却。不同频道或重开鱼塘不重置，服务器重启后继续从数据库读取。不同独立服务器是不同账号，不做金币和收藏跨服务器同步。
- 计时由服务器记录。在读取鱼塘或行动时结算已到时的自动收杆和鱼游走。客户端窗口每 2 秒读取一次，AI 每 3 秒关注自己坐着的鱼塘。没有人在线查看时不循环产出收益，再次读取至多结算一条具备自动收杆条件的积压收获。结界和手套结算也遵守服务器时间。
- 普通竿免费自带。背包满时鱼被放生，有提示。默认鱼篓 1000 条、未开卡包 1000 包。鱼塘使用现有每会话同时游戏数量限制 `limits.max_games_per_conv`。

## 100 种幻想鱼与长度

权威图鉴是 [`server/internal/game/fishing_rules.json`](../server/internal/game/fishing_rules.json)，含 100 个唯一 ID、名称、平均长度、基础价值、稀有度、矢量外形、花纹和说明。客户端直接读取服务端图鉴绘制图像，不连外部素材网站。同一个 ID 在卡面和鱼获中对应同一种鱼。

| 鱼种稀有度 | 常见 | 奇异 | 稀有 | 史诗 | 传说 |
| --- | --- | --- | --- | --- | --- |
| 种数 | 20 | 20 | 20 | 20 | 20 |
| 默认权重 | 55 | 25 | 12 | 6 | 2 |

先抽鱼种档位，再等概率抽该档一条鱼。长度另外抽五档变异（寻常、出众、罕见、极端、奇迹），默认权重 52/28/13/6/1。各档偏差系数 0.18/0.35/0.6/0.9/1.5，再乘 `[0.8,1)` 随机浮动，等概率取 `平均长度 × (1 ± tanh(偏差))`，保留两位小数。越极端越不容易，长和短都能珍贵，平均值不会因为只奖励大鱼而偏移。

价值为基础价值乘以变异档倍率 1/1.5/2.5/5/12，再乘已装备点金竿的加成，四舍五入为整币。每个鱼种记录自己钓到的最短与最长个体，卖出仍保留历史纪录，但历史纪录不能代替已经卖掉的鱼展示。主页只能挂鱼篓里仍持有的本人钓获。偷来的鱼可出售，不算自己的钓获纪录，也不能挂作本人鱼获。

每次收获默认 93% 是鱼、4% 钱袋、2.5% 单张卡、0.5% 卡包。钱袋默认 15–85 币，包含两端。满卡包时卡包掉落改抽鱼。鱼篓满时放生鱼，不自动卖。

## 商店与工具

卖鱼需要明确选择鱼获 ID，服务端检查全都属于自己的鱼篓，重复 ID 拒绝。每条鱼按捕获时已经确定的价值卖出，后来换装备不会改价。

五种工具各有五档品质，价格为 120/450/1500/5000/16000 币，购买更高档替换当前品质，按该档全价购买、不返还旧款。可以直接买高档。最多同时装备两类，同类一件。卸下、换品质、跨频道都不清冷却。

| 工具 | 五档效果 |
| --- | --- |
| 疾风钓竿 `speed` | 等待缩短 12/22/32/42/55% |
| 机械钓竿 `auto` | 自动收杆一次，冷却 150/120/90/65/40 秒 |
| 点金钓竿 `value` | 鱼获价值提高 15/30/55/90/150% |
| 幻影手套 `glove` | 偷钩上收获成功率 35/48/62/78/95%，冷却 180/145/110/80/50 秒 |
| 守鱼结界 `ward` | 自动挡一次偷鱼，冷却 180/145/110/80/50 秒 |

手套只可对本鱼塘别的已上钩、尚未收杆的座位使用。结界就绪时先挡住，保留原钩，消耗双方对应冷却。没有结界时再按手套成功率判定，失败也消耗手套冷却并保留原钩。成功把这一钩收获给偷取者，目标重新抛竿。由于收杆前不揭晓钩上是什么，也可能偷到钱袋、卡或卡包。

自动收杆只能在上钩窗口内有一次冷却就绪点时结算，过了窗口才冷却完则鱼游走。钓竿、卡包都只用游戏币，不含充值和真实货币。

## 鱼卡与徽章

- 每包 180 币，四张独立抽取。卡片鱼种等概率抽 100 种之一。
- 卡片档位铁、铜、银、金、镭射，默认权重 60/25/10/4/1，共 500 种组合。重复卡保留数量，不增加唯一收集进度。开包和单卡掉落都更新进度。
- 每档拥有不同鱼卡 25/50/75/100 种，自动获得该档 I/II/III/IV 级徽章，低级也保留。徽章用对应金属色的六边形星章和绶带，卡面镭射使用渐变光泽。没有卡片交易或销毁机制。

## 主页三个组件

仅用户主页可用，服务器主页不支持。展示端只读服务器保存的本人纪录、已拥有的卡和徽章，不信任组件配置里的金币、长度和卡数量。

| kind | 配置 | 容量 |
| --- | --- | --- |
| `fishing_fish` | `ids` 选择仍持有的本人鱼获 ID（十进制字符串） | floor(宽×高 / 2)，横宽竖放、纵长横放。可选择鱼篓里仍持有的本人钓获，卖掉后不再展示 |
| `fishing_cards` | `mode: cards` 与 `ids`（`0:f001` 等），或 `mode: progress` | 每格一张，进度模式显示五档各 /100 |
| `fishing_badges` | `{}` | 全部已解锁的徽章，超出区域可滚动 |

公开展示将已保存主页选择的个体 ID 与当前鱼篓逐条核对，必须仍持有且原捕获账号是本人。卖掉后接口立即不再提供该鱼，旧配置和历史纪录均不能恢复它，未选择的鱼篓个体不会公开。同一客户端成交后立即刷新组件，其他正在查看的客户端每 10 秒刷新收藏展示。

编辑器提供收藏选择器，缩小组件时截取能展示的数量。服务端检查数量不能超过格数。公开展示接口不会输出钱包、私有鱼篓、装备、冷却和当前鱼塘。

## AI

`open_game(kind=fishing)`、`join_game`、`leave_game` 直接可用。`fishing_state` 给 AI 完整规则、100 鱼图鉴、服务端平衡参数和自己的账号。`fishing_act` 支持 `sit/reel/steal`，`fishing_shop` 支持卖鱼、购置和装备工具、买包开包。座位号对模型从 1 开始。AI 按主人原有游戏参与设置决定是否加入，入座后用同样接口关注上钩并收杆，不为每条鱼调用一次模型，也不在频道逐条报鱼获。工具权限仍属于现有 `games` 分类。

## 接口和数据

协议先在 `api.proto` 中定义 `FishingData{state_json}` 与 `FishingActionRequest`，生成 Go/TS。JSON 版本 1，结构与服务端 `FishingAccount`、`FishingRules`、`Pond` 一致，所有用户、鱼获和鱼塘的 int64 标识在 JSON 中使用十进制字符串，避免 JavaScript 丢失精度。

- `GET /api/v1/fishing/rules` → `FishingData`，图鉴及当前平衡配置。
- `GET /api/v1/fishing/me` → `FishingData`，只返回当前认证账号。
- `POST /api/v1/fishing/me` ← `FishingActionRequest{action,item,quality,fish_ids,request_id}` → `FishingData`。动作 sell / buy_tool / equip / unequip / buy_pack / open_pack。请求编号 8–64 字符。每个新操作新编号，网络失败重试原编号。同一账号的编号永久去重，换参数重用报 `bad_request`。客户端在当前游戏窗口保留待重试编号，成功后清除。
- `GET /api/v1/users/{id}/fishing-showcase` → `FishingData{records,cards,badges}`，要求登录，不返回私有钱包。
- 现有 `/conversations/{id}/games` 的 kind 加 `fishing`。`Game.state_json` 加 `pond{seats[12],now}`，空座 `user_id="0"`，非空有 `bite_at/expires_at` 毫秒时间。`/games/{id}/act` 的 action 加 `sit`（target 空座 0–11）/ `reel` / `steal`（target 0–11）。普通 `join/leave/end` 复用现有路由。没有桌游式 start 和 rematch，重开需新开鱼塘。
- 未授权沿用 `not_member/no_permission`，不合法经济操作或未上钩沿用 `game_bad_move`，同账号已在别处钓鱼沿用 `game_state`，满座 `game_full`。不存在的展示用户沿用 `not_found`。

数据库迁移 `0023_fishing.sql` 在 SQLite/PostgreSQL 各新增 `fishing_accounts`（每账号一份 JSON）、`fishing_actions`（请求去重账本）。鱼塘依然存在现有 `games` JSON 行。交易锁账号，鱼塘动作先锁局再按账号 ID 升序锁涉及的账号，同事务保存收获、钱包和鱼塘，防止两个客户端同时领、卖、偷。卖鱼会影响主页的持有状态，玩家需要在保留展示与出售换币之间选择。SQL 仅在 store 包。

## 平衡配置

默认所有平衡参数及图鉴都在内嵌 `fishing_rules.json`。想调整时把完整 JSON 复制到服务器目录，比如 `data/fishing-rules.json`，在 `config.toml` 的 `[fishing] rules_file = "data/fishing-rules.json"` 指向它，重启生效。空字符串使用内置数据。禁止缺档、空分布、超界数字和重复鱼种，配置无效拒绝启动。分布中某项写 0 可关闭该掉落，整体权重必须为正。

上线后不要改变鱼的 ID，也不要删除旧 ID，卡和纪录以此保存。调整平均长度与基础价值只影响新鱼获，已有鱼获价值不变。

- 规则单测覆盖 100 唯一鱼种、无效平衡配置、卡片去重与徽章里程碑、偷取不写本人纪录。
- 服务端 e2e 在 SQLite / CI PostgreSQL 覆盖 12 座、权限、同账号跨塘限制、收杆时间窗、重复请求与并发购买、卖鱼、两类工具、结界/手套、自动竿冷却、跨频道存档和公开字段隔离。
- `npm test` 覆盖展示容量、卡片唯一数、int64 字符串与真实 Session 请求入口。
- 可选 `cd client && npm install --no-save --package-lock=false playwright && npx playwright install chromium && node e2e/fishing-browser.mjs`，验证真实组件 12 座、商店不改公共鱼塘、购买、100 鱼图鉴、主页卖鱼后隐藏与手机宽度。CI 自动执行并保存截图。
