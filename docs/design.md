# AM 设计文档

> 本文件是设计基准。claude.ai 上的讨论稿只作历史参考，有冲突以这里为准。
> 最后更新：2026-10-29（第一阶段第 4 批）

## 1. 原则

- **协议先行**：消息协议和数据结构先定死、写成文档，再写代码。加功能是加新事件类型，不推翻旧结构。
- **模块边界清楚**：后端是一个程序，内部按模块分包；只有 `store` 碰数据库，只有 `gateway` 维持连接。
- **身份由服务器盖章**：bot / AI 标识、插件公示这类"不能撒谎"的信息，一律由服务器生成，客户端只负责显示。
- **消息只追加，不抹除**：普通用户只能划掉，不能撤回；管理员删除对用户不可见，但服务器保留证据和记录。
- **文档和代码同仓库**：每次开工先读文档，再改对应模块。

暂不考虑：商业化、联邦互通、聊天内容端到端加密。合规义务见第 15 节。

## 2. 已定决策

| 项目 | 决定 |
| --- | --- |
| 开发方式 | 从零自研，不基于 Matrix 等现成框架 |
| 分发模式 | 发布的是软件：带界面的客户端 + 服务器。服务器由用户自己搭，客户端用加入码 / 二维码连接（见第 3 节）。不搭官方大型服务器，不涉及备案 |
| 后端 | Go；数据库默认 SQLite（单文件、免安装），可切换 PostgreSQL；第一阶段不用 Redis |
| 客户端 | React + TypeScript，Tauri 2 打包 Windows / 安卓。不做纯网页版（网页不能信任自签证书）。界面风格参考 NapCatQQ 的客户端，要好看 |
| 客户端更新 | 外壳 + 可热更新的界面包；界面更新不用重装；更新从 GitHub Releases 拉取（以后可加镜像），不经各自建服务器 |
| 创意工坊 | 托管在 GitHub：索引仓库 + 作者仓库的 Release，PR 审核上架，不需要官方服务器；侧载未审核内容需开发者开关，加载时警告并公示（见第 13 节） |
| 协议定义 | Protobuf 一份定义，生成 Go 和 TS 代码；WebSocket 用二进制 protobuf，HTTP 用 protojson |
| 撤回 | 改为"划掉"：删除线 + 标记，原文仍可见，不可撤销 |
| 编辑 | 不提供。发错只能划掉重发 |
| 管理员删除 | 对所有用户消失，原位置留删除记录；内容移入违规证据区保留 6 个月（可配置）后自动清除 |
| 日志留存 | 登录记录（时间、IP、设备）至少保留 6 个月 |
| 实名 | 数据库预留实名字段，现阶段不启用；对外开放前接手机号验证 |
| bot / AI | 不限功能；必须标明 AI 身份和主人 |
| 普通账号挂 AI | 检测标记 → 管理员确认 → 封禁；举报查实直接封 |
| 内容规则 | 鉴政一律封号 |
| 海外模式开关 | 不做。若做国际版，部署为完全独立的一套服务（账号、数据分开），客户端不放切换开关 |
| AI key | 客户端用密码派生的密钥加密后存服务器，登录时下载，客户端直接调用 |
| 注册方式 | 邀请码注册。每个账号注册后自动获得 3 个邀请码（可配置），在客户端里以加入码 / 二维码发给朋友；管理面板不生成邀请码，只能查看和作废。第一个账号用服务器窗口里的管理员加入码注册，成为站点管理员 |
| 全员禁言 | 不做 |
| 外部表情包搜索 | 预留"搜索源"接口，暂不实现（Tenor API 已于 2026-06-30 关停） |
| 部署（第一阶段） | 13600 + 阿里云 5M frp 中转，不用域名，客户端直连 IP + 端口，自签证书 + 指纹固定 |
| 大规模后的媒体 | 预留：媒体访问都走 media 模块，自建服务器以后想换对象存储只改这一处。现阶段不做 |

## 3. 分发与自建

- 发布到 GitHub 的是工具：客户端（Windows / 安卓）和服务器 `am-server`。每个人可以自己搭服务器，邀请朋友来用。各服务器上的内容由搭建者自己负责。
- **服务器**：一个文件 `am-server.exe`，双击就跑：不弹黑框，任务栏右下角有托盘图标，自动在**独立窗口**里打开管理面板（WebView2，Win10/11 自带；没有时退回浏览器）。窗口是单独的 am-server 子进程（`window` 命令），关掉窗口服务器照样在托盘运行，窗口出问题也不会拖垮服务器。第一次启动自动生成配置、数据库（SQLite）、证书和管理员加入码。再双击一次不会开第二个，只会把窗口调出来。
  - 管理面板是 am-server 内嵌的网页（`server/internal/admin`，纯 JS，无构建步骤），默认只监听 `127.0.0.1:8444`。登录用 `data/admin_key.txt` 里的密钥，托盘图标打开时自动登录。功能：概览（首次：管理员加入码 + 二维码；之后：服务器码，用于已有账号在新设备上添加服务器）、用户（封禁 / 解封、重置密码、设管理员、登录记录）、邀请码（查看谁邀请了谁、作废）、删除记录（证据区）、操作记录（审计日志）、运行日志、设置（表单 + 直接编辑 config.toml，保存前校验，旧版本存 .bak）、开机自启、重启 / 退出。
  - 聊天服务在可重启的循环里运行（`supervisor`），面板一直在线：配置写错或端口被占时面板显示原因，改好设置点重试即可，不用碰命令行。
  - Linux 云服务器用同一份代码（`-headless`，无托盘、不开浏览器），面板通过 SSH 隧道访问。
  - 配置里的相对路径（`data_dir` 等）以配置文件所在文件夹为准；Windows 下默认配置文件在 exe 旁边。
- **加入码**：服务器地址、端口、证书指纹（前 16 字节）和邀请码打包加扰成一串 `AM1-XXXX-...`，不明文露出 IP（只是防一般人看到，不算保密：客户端要能解开才能连）。不带邀请码的叫"服务器码"，用于已有账号在新设备上添加服务器。格式见 protocol.md。
  - 二维码内容是 `<下载页>#join=<加入码>`：别的软件扫码打开客户端下载页（默认 GitHub Releases，`invites.download_url` 可改），AM 客户端扫码直接读出加入码进入注册页。
  - 服务器知道公网地址（`server.public_address`）时，邀请码列表里直接带加入码；不知道时客户端用自己连接的地址拼出来。
  - 客户端可保存多个服务器。
- **自签证书与客户端**：浏览器和 WebView 不能按指纹信任自签证书，所以 Tauri 客户端的联网由程序本体（Tauri 的 Rust 部分）负责，按加入码里的指纹校验，界面通过 IPC 调用。因此不做纯网页版客户端。
- **协议版本**：服务器和客户端互报协议版本；客户端太旧时提示更新。
- **创意工坊**：官方运营的独立服务（`am-workshop`），是唯一连到官方服务器的部分。
  - 创作者用 GitHub 账号登录、从 GitHub 仓库提交；浏览和下载不需要账号。
  - 审核通过的内容由工坊私钥签名，客户端 / 服务器内置公钥验签，验签通过才算"已审核"。
  - **侧载**：开发者可在客户端打开"开发者模式"加载本地未审核内容，加载时弹警告，个人资料页公示"侧载（未审核）"。每个服务器的管理员可在配置里禁用侧载。
  - 工坊是官方公开分发用户上传内容的平台，审核责任在官方，必须严格审核。

## 4. 架构

```
客户端（Windows / 安卓 / Bot 程序）
   │ WebSocket（实时）        │ HTTP（登录、好友、上传等）
   ▼                          ▼
┌──────────── am-server（Go，单个可执行文件）────────────┐
│ supervisor：可重启的服务循环   admin：管理面板（仅本机）  desktop：托盘 │
│ gateway：连接与推送        httpapi：HTTP 接口          │
│ account │ conv │ message │（后续：media admin bot ai sticker community workshop）│
│ store：唯一读写数据库的模块                              │
└─────────────────────────────────────────────────────────┘
   ▼
SQLite 或 PostgreSQL ／ 文件存储 ／ 违规证据区
AI 服务商 ← 客户端直连（不经服务器）
官方创意工坊 ← 客户端只在浏览 / 下载工坊内容时连接
```

## 5. 客户端

**技术栈**：Tauri 2（Rust 外壳）+ React 19 + TypeScript + Vite + Tailwind CSS 4 + motion（动画）+ zustand（状态）。界面组件自己写（`client/src/ui`），不依赖组件库。代码在 `client/`，界面在 `client/src`，外壳在 `client/src-tauri`。先做 Windows，安卓以后用同一份代码（Tauri 2 支持安卓）。苹果不做（上架和签名要每年 99 美元的开发者账号）。

**联网**

- 桌面版里所有请求都由 Rust 部分发出（`src-tauri/src/net.rs`：reqwest + rustls + tokio-tungstenite），按加入码里的证书指纹校验自签证书；没有指纹（正式证书）时按系统根证书校验。界面通过 Tauri 命令调用（`api` / `upload` / `download` / `ws_open` ...），WebSocket 帧经 Channel 传回界面。
- 图片、头像等媒体走自定义协议 `ammedia://`，由 Rust 带上登录令牌去服务器取，界面直接 `<img src>`。
- 浏览器开发模式（`npm run dev`）没有 Rust 部分：Vite 把 `/api`、`/ws` 代理到本机一个关掉 TLS 的 am-server。只用于开发和自动化测试，不是网页版。
- 协议代码由 `buf generate` 生成到 `client/src/gen`（protoc-gen-es），HTTP 用 protojson，WebSocket 用二进制 protobuf，和服务器同一份 proto。

**功能（第 4 批）**：多服务器（会话列表顶部切换）；加入码 / 二维码注册登录，启动时读剪贴板，发现加入码直接提示；私聊、群聊、文字 / 表情 / 图片 / 文件（粘贴、拖拽）；划掉、管理员删除；群成员管理和入群审批；好友和好友申请；个人资料、邀请码（加入码 + 二维码）、登录设备和登录记录；断线自动重连并补消息；窗口不在前台时弹系统通知。

**界面风格**：参考 NapCatQQ 客户端——渐变背景 + 模糊光斑、近白色卡片、圆角。阴影浅而大、四周都有、没有硬边；鼠标移上去卡片抬高、阴影扩大，按下压低；动画全部用非线性曲线（ease-out / 弹簧），页面、弹窗、菜单、导航指示条都有过渡。

**防重复点击**：凡是要等服务器的操作，对应按钮 / 开关 / 菜单项在请求完成前显示加载并且不能再点。做在组件里（按钮的 onClick 返回 Promise 就自动进入加载状态；确认弹窗的"确定"等操作完成再关；菜单项同一操作进行中不重复执行），新加的按钮自动具备。

**导航**：最左边一栏是总导航（消息、联系人、AI，以后加工坊、社区；底部是设置和"我"）。和 bot / AI 账号的私聊不出现在"消息"里，统一放在 AI 栏（见第 9 节）。

**个性化**（只存在本机）：浅色 / 深色 / 跟随系统；主题色（6 个预设 + 自定义颜色）；导入背景图片（可调模糊和遮罩）；字体大小。以后创意工坊的"主题"可以一键套用这些设置（见第 13 节）。

**更新**

- 客户端分两层：**外壳**（Tauri 程序本体，提供窗口、通知、文件、联网等底层能力，很少变）和**界面包**（网页代码，经常变）。
- 界面包：客户端启动时从发布渠道（GitHub Releases，以后可加镜像）查询最新版本，后台下载，下次启动生效。界面包必须带签名（发布时用私钥签，客户端内置公钥验签），验签失败不加载，回退到上一个版本。
- 外壳：底层功能变化时才更新，用 Tauri 官方自动更新插件，同样验签，点一下重启即完成。
- 界面包声明它需要的最低外壳版本；外壳太旧时提示先更新外壳。

## 6. 消息模型

会话里的一切都是事件（`am.v1.Event`），只追加：

- `event_id`：64 位按时间递增的全局 ID（雪花算法）。
- `seq`：会话内从 1 开始、无空缺的序号。断线重连按 seq 补缺。
- `client_msg_id`：客户端生成的去重 ID，网络重发不会产生两条；只回给发送者本人。
- 事件体是 oneof：文字、图片、文件、划掉、管理员删除、成员变动、会话信息变动。

**规则**

- 划掉：只能划自己的文字 / 图片 / 文件消息，随时可划，每条只能划一次，不可撤销。
- 管理员删除：
  - 对用户：目标事件的正文不再下发，事件带 `redaction`（删除者、原因、时间），另追加一条 `admin_delete` 事件。
  - 对服务器：正文和文件移入违规证据区（只有站点管理员可查看），保留期满自动清除；删除动作写审计日志；图片感知哈希进黑名单。
- 普通用户没有任何删除接口。
- 未读数 = 会话 last_seq − 自己的 read_seq。

## 7. 账号与身份

| 类型 | 创建方式 | 显示 |
| --- | --- | --- |
| human | 邀请码注册 | 正常 |
| bot | 主人在"我的 bot"里创建 | 「Bot · 主人：xx」 |
| ai | 同上，选 AI 类型；私人 AI 拉进群也是这类 | 「AI · 主人：xx」 |

- bot / ai 没有密码，只能用主人生成的 token；主人被封，名下 bot 一起停用。
- 密码 Argon2id；每台设备一个会话 token（服务器只存 SHA-256），可逐个踢下线，踢掉立即断开连接。
- 登录记录（时间、IP、设备名）单独存表，保留 6 个月以上。

**个人资料**

- 头像支持 GIF（以后可服务器转码为体积更小的动图格式）。列表、聊天里显示静态首帧，进入个人主页才播放动画，避免占满带宽。
- 个人主页是类似手机桌面的网格，可自行摆放小组件。布局存为 JSON：每个组件的位置、大小、组件 ID 与版本、组件配置。
- 先做内置组件（签名、在玩的游戏、照片墙、留言板等），工坊组件放在第五阶段。
- 访客打开主页时，组件代码在访客设备上运行，所以组件沙盒比插件更严：拿不到访客任何数据、无网络权限、限制 CPU 和内存。

## 8. 会话与群

- 私聊：两人会话，必须是好友才能发起；同一对用户只有一个私聊。
- 群聊：群主 / 管理员 / 成员。成员可邀请好友（开了入群审批时要管理员同意）；第二阶段加"添加 bot"，只能添加自己的 bot。管理员可改群信息、踢人、禁言成员（不能动管理员）、删除他人消息（留记录）、入群审批；群主额外可设管理员、转让、解散。
- 个人设置：置顶（可排序）、免打扰（可设到期）、群备注、已读位置。

## 9. AI 对话栏（第二阶段）

**接入**

- 适配器：一个 OpenAI 兼容通用适配器（DeepSeek、xAI、OpenRouter 等），Claude、Gemini 各一个原生适配器。新增服务商 = 新增一个适配器文件。
- 余额：能查的服务商显示余额并低余额提醒；"去充值"按钮跳官方充值页。代充 / 转售暂不做。
- key：用登录密码 + 独立盐（Argon2id）在本机派生密钥，加密后上传；新设备下载解密；忘记密码需重填 key。
- 跨域：Tauri 从程序本体发请求，不受浏览器跨域限制。

**AI 栏界面**

- 三栏：总导航 | AI 列表 | 聊天。AI 列表分"我的 AI"和"添加的 AI"（别人的，标明主人是谁）。和 bot / AI 账号的私聊都在这里，不在"消息"列表里；从联系人或群成员里点 bot 的"发消息"也会跳到这里。
- 聊天窗口和普通聊天大体一样（文字、表情、上传文件、语音输入），但上半部分是 AI 形象立绘，随情绪切换。
- 在这里发表情包，AI 收到的只是表情包的标签（表情包库带关键词 / 标签，见第 11 节），不传图片。
- 第 4 批先做了框架：列表、跳转、立绘区（暂时显示大头像，离线变灰）。创建 bot、立绘随情绪切换、语音输入在第二阶段做。

**AI 形象**

- 形象包 = 一组按情绪命名的图片，文件名就是情绪名（如 `happy.gif`）。支持 PNG / WebP / GIF / APNG，动图会动；列表等小地方只显示第一帧。名字统一，形象包才能通用；形象包可附加额外情绪。
- 标准情绪 16 种 + 状态 2 种。只有 `neutral` 必须有，缺的按右边的顺序找替代（再缺就用 `neutral`）：

  | 名字 | 含义 | 缺了用 |
  | --- | --- | --- |
  | `neutral` | 普通（必需） | — |
  | `happy` | 高兴 | neutral |
  | `laugh` | 大笑 | happy |
  | `smug` | 得意 | happy |
  | `shy` | 害羞 | neutral |
  | `love` | 喜欢 | shy |
  | `sad` | 伤心 | neutral |
  | `cry` | 哭 | sad |
  | `worried` | 担心 | sad |
  | `scared` | 害怕 | surprised |
  | `angry` | 生气 | neutral |
  | `surprised` | 惊讶 | neutral |
  | `thinking` | 思考 | neutral |
  | `confused` | 疑惑 | thinking |
  | `speechless` | 无语 | confused |
  | `sleepy` | 困 | neutral |
  | `typing` | 状态：正在回复 | thinking |
  | `offline` | 状态：主人离线，AI 回不了话 | `neutral` 变灰 |

- 素材建议：正方形 512×512（不小于 256），透明背景，每张不超过 3 MB；同一套里人物大小、位置一致（半身，脸在中上部），切换时才不跳。
- 回复带情绪：系统提示要求模型在回复开头输出 `[mood:xxx]`（xxx 为上表情绪名，不含两个状态），客户端解析后切换图片并从显示内容中去掉标签；解析失败用 `neutral`。等待回复时显示 `typing`，主人离线时显示 `offline`。不依赖任何一家的特殊功能。
- 形象包可上传工坊，审核注意版权（直接使用他人角色原图的不予通过）。

**人格设定**

- 一个人格包含：名字、简介、系统提示、示例对话、开场白、推荐服务商与模型、参数（温度等），可选绑定形象包。
- 内置几个默认人格，用户可自建；自建人格可上传工坊，上传内容即上述全部字段。下载者用自己的 key 调用；没有推荐的服务商时提示改用其他模型。
- 人格也可用于拉进群的 AI。审核重点：诱导点外链、借人格绕过服务商审核。

**私人 AI 进群**

- 是 ai 账号，调用发生在主人客户端，主人在线才回话。
- 离线期间被 @ 的问题，上线后按配置补回（最近 N 小时、最多 N 条），回复引用原问题并标明"离线期间的提问"。
- 入口两个：在 AI 栏里把自己的 bot 邀请进某个群；在群里点 bot 头像"添加到 AI 栏"（别人的 bot 进自己的 AI 栏 = 申请共用，见下）。
- 群里除了"邀请好友"，还有"添加 bot"按钮，只能添加自己的 bot（服务器校验主人）。

**共享 AI**

- 可以和朋友共用一个 AI：在 AI 栏里一起跟它聊，聊天记录和记忆共享。必须经 bot 主人同意，主人可随时移除成员。
- key 只在主人设备上，所以朋友的消息由主人的客户端代为调用、用主人的额度，主人在线才回复（和群里的私人 AI 一样）。主人可设每人每天的条数上限。
- 共享会话的记录和记忆存在服务器上（一种特殊会话，成员 = 主人 + 被批准的朋友），换设备不丢。

## 10. Bot（第二阶段）

- 单独一栏管理自己的 bot，两种模式：本机运行 / 托管到服务器。
- 托管先只做"配置型 bot"（选模型 + key + 提示词 + 触发规则），任意代码托管以后再说（需要容器隔离），并可做成付费；数据库预留配额字段。托管模式下 key 需交给服务器使用，界面明确提示。
- 原生接口与客户端相同；另有 OneBot v11 兼容层，NoneBot2 插件改连接配置即可搬来。

## 11. 表情包（第三阶段）

- 全站共享库，感知哈希去重，显示最早上传者；个人收藏夹多对多引用；客户端按文件哈希本地缓存，同一张只下载一次。
- 搜索：先关键词 + 标签；再用 5060 后台慢慢跑 OCR + CLIP 建索引（pgvector），搜索时只需把搜索词转成向量，CPU 也够。
- 外部搜索源接口预留；外部图片经服务器代理缓存，用户发出时自动收录。

## 12. 社区（第四阶段）

好友动态 / 公开广场；发布选"公开"或"仅好友"；评论也只能划掉；帖子带举报计数和隐藏字段，管理员隐藏留记录。内置主页小组件在本阶段一起做。

## 13. 创意工坊（第五阶段）

**内容类型**：小游戏、功能插件、AI 形象包、人格设定、主页小组件、主题。

- 主题：主题色、深浅色、背景图（含模糊 / 遮罩）、字体大小的一组设置，下载后一键套用，就是客户端"外观"设置里能改的那些。

- 程序类内容（小游戏、插件、组件）是网页小程序，跑在沙盒 iframe，只能调平台接口，安装时弹权限清单，网络走白名单代理。
**托管：全部放在 GitHub，不需要官方服务器**（类似 AstrBot 插件市场最早的做法）

- 索引仓库 `am-workshop`：一个索引文件，记每个内容的类型、作者、仓库、版本、Release 文件地址和 SHA-256。客户端从这里拉列表，下载后核对 SHA-256，被改过就拒绝安装。
- 内容本身放在作者自己仓库的 Release 里（源码公开），作者打版本标签发布。
- 上架 = 向索引仓库提 PR：GitHub Actions 自动检查格式、拉源码跑 AI 审核（对照声明权限读源码，拒收混淆代码），结果写在 PR 里；官方人工看过后合并即上架。高权限内容必须人工复核。上架后靠举报（索引仓库 issue）。
- 下架 / 远程停用：索引里标记停用，客户端同步索引后禁用。
- 排行：用 GitHub Release 自带的下载次数做总榜，定时任务（Actions）记快照算周榜；搜索在客户端对索引做（量大再换）。
- 国内访问 GitHub 可能慢：客户端留"下载镜像地址"配置。
- 公示：资料页显示已开插件及关键权限（由各自建服务器下发）。

## 14. 规模化预留

1. 按时间递增的消息 ID。
2. 会话内递增 seq，同步量只和离线时长有关。
3. 存储层隔离（`store` 包），同一套方法支持 SQLite 和 PostgreSQL。
4. 连接层（gateway）与业务层分开，模块经 `push.Pusher` 推送。
5. 媒体访问统一走 media 模块，以后切换到对象存储 + CDN 只改这一处。

**带宽参考（5 Mbps 中转 ≈ 每秒 0.6 MB）**：文字几乎不占带宽；10 人以内随便用；50 人活跃群在做好缩略图、表情缓存、动图不自动播放、文件限大小后，10–20 Mbps 比较宽裕。家里宽带上行也是上限。

## 15. 合规备忘

> 不是法律意见，正式对外前请律师过一遍。

- 法规对"上线"本身就有要求，没有"多少人以下不用管"的人数门槛。例如《具有舆论属性或社会动员能力的互联网信息服务安全评估规定》：开办聊天室、通讯群组、论坛等服务上线时，或用户规模显著增加时，应自行开展安全评估。
- 实际上被关注的程度，主要看是否面向**不特定公众**：开放注册（不需邀请码）、应用商店上架或公开下载链接、陌生人可见的公开广场、可被搜索引擎收录、收费。出现这些之前，应补齐：
  - 备案（服务器在大陆且使用域名）；
  - 后台实名、前台自愿（手机号验证）；
  - 网络日志留存不少于 6 个月；
  - 违法信息处置、拉黑、保存记录并向主管部门报告的流程；
  - 安全评估。
- 刑事风险最重的是拒不履行信息网络安全管理义务罪，前提是被监管部门责令改正后仍拒不改正。被要求整改时必须配合。
- 管理员删除保留证据（第 6 节）正是为了不造成"证据灭失"。
- 自建模式下，各服务器的合规由搭建者负责；官方需负责的是创意工坊（公开分发的用户内容）。
