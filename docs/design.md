# AM 设计文档

> 本文件是仓库内的设计基准，和 claude.ai 上的讨论稿保持一致；有改动以这里为准。
> 最后更新：2026-10-29

## 1. 原则

- **协议先行**：消息协议和数据结构先定死、写成文档，再写代码。加功能是加新事件类型，不推翻旧结构。
- **模块边界清楚**：后端是一个程序，内部按模块分包；只有 `store` 碰数据库，只有 `gateway` 维持连接。
- **身份由服务器盖章**：bot / AI 标识、插件公示这类"不能撒谎"的信息，一律由服务器生成，客户端只负责显示。
- **消息只追加，不抹除**：普通用户只能划掉，不能撤回；管理员删除会留下记录。
- **文档和代码同仓库**：每次开工先读文档，再改对应模块。

暂不考虑：备案、法律合规、商业化、联邦互通、聊天内容端到端加密。

## 2. 已定决策

| 项目 | 决定 |
| --- | --- |
| 开发方式 | 从零自研，不基于 Matrix 等现成框架 |
| 后端 | Go + PostgreSQL（第一阶段不用 Redis，单机内存即可；多开 gateway 时再加） |
| 客户端 | React + TypeScript，Tauri 2 打包 Windows / 安卓 |
| 协议定义 | Protobuf 一份定义，生成 Go 和 TS 代码；WebSocket 用二进制 protobuf，HTTP 用 protojson |
| 撤回 | 改为"划掉"：删除线 + 标记，原文仍可见，不可撤销 |
| 编辑 | 不提供。发错只能划掉重发 |
| 管理员删除 | 内容真删，原位置留删除记录（谁、何时、原因） |
| bot / AI | 不限功能；必须标明 AI 身份和主人 |
| 普通账号挂 AI | 检测标记 → 管理员确认 → 封禁；举报查实直接封 |
| AI key | 客户端用密码派生的密钥加密后存服务器，登录时下载，客户端直接调用 |
| 注册方式 | 邀请码注册，每人 3 个（配置文件可改）；第一个账号用启动码注册，成为站点管理员 |
| 全员禁言 | 不做 |
| 外部表情包搜索 | 预留"搜索源"接口，暂不实现（Tenor API 已于 2026-06-30 关停） |
| 部署（第一阶段） | 13600 + 阿里云 5M frp 中转，不用域名，客户端直连 IP + 端口，自签证书 + 指纹固定 |

## 3. 架构

```
客户端（网页 / Windows / 安卓 / Bot 程序）
   │ WebSocket（实时）        │ HTTP（登录、好友、上传等）
   ▼                          ▼
┌──────────── am-server（Go，单个可执行文件）────────────┐
│ gateway：连接与推送        httpapi：HTTP 接口          │
│ account │ conv │ message │（后续：media admin bot ai sticker community workshop）│
│ store：唯一读写数据库的模块                              │
└─────────────────────────────────────────────────────────┘
   ▼
PostgreSQL ／ 文件存储
AI 服务商 ← 客户端直连（不经服务器）
```

## 4. 消息模型

会话里的一切都是事件（`am.v1.Event`），只追加：

- `event_id`：64 位按时间递增的全局 ID（雪花算法）。
- `seq`：会话内从 1 开始、无空缺的序号。断线重连按 seq 补缺。
- `client_msg_id`：客户端生成的去重 ID，网络重发不会产生两条；只回给发送者本人。
- 事件体是 oneof：文字、图片、文件、划掉、管理员删除、成员变动、会话信息变动。

**规则**

- 划掉：只能划自己的文字 / 图片 / 文件消息，随时可划，每条只能划一次，不可撤销。
- 管理员删除：正文和文件真删，事件留下 `redaction`（删除者、原因、时间），写审计日志，图片感知哈希进黑名单。
- 普通用户没有任何删除接口。
- 未读数 = 会话 last_seq − 自己的 read_seq。

## 5. 账号与身份

| 类型 | 创建方式 | 显示 |
| --- | --- | --- |
| human | 邀请码注册 | 正常 |
| bot | 主人在"我的 bot"里创建 | 「Bot · 主人：xx」 |
| ai | 同上，选 AI 类型；私人 AI 拉进群也是这类 | 「AI · 主人：xx」 |

- bot / ai 没有密码，只能用主人生成的 token；主人被封，名下 bot 一起停用。
- 密码 Argon2id；每台设备一个会话 token（服务器只存 SHA-256），可逐个踢下线，踢掉立即断开连接。

## 6. 会话与群

- 私聊：两人会话，必须是好友才能发起；同一对用户只有一个私聊。
- 群聊：群主 / 管理员 / 成员。管理员可改群信息、踢人、禁言成员（不能动管理员）、删除他人消息（留记录）、入群审批；群主额外可设管理员、转让、解散。
- 个人设置：置顶（可排序）、免打扰（可设到期）、群备注、已读位置。

## 7. AI 对话栏（第二阶段）

- 适配器：一个 OpenAI 兼容通用适配器（DeepSeek、xAI、OpenRouter 等），Claude、Gemini 各一个原生适配器。
- 余额：能查的服务商显示余额并低余额提醒；"去充值"按钮跳官方充值页。代充 / 转售暂不做。
- key：用登录密码 + 独立盐（Argon2id）在本机派生密钥，加密后上传；新设备下载解密；忘记密码需重填 key。
- 跨域：Tauri 版用官方 HTTP 插件从底层发请求；纯网页版受浏览器限制，能用几家算几家。
- 私人 AI 进群：是 ai 账号，调用发生在主人客户端，主人在线才回话；离线期间被 @ 的问题，上线后按配置补回（最近 N 小时、最多 N 条，标明"离线期间的提问"）。

## 8. Bot（第二阶段）

- 单独一栏管理自己的 bot，两种模式：本机运行 / 托管到服务器。
- 托管先只做"配置型 bot"（选模型 + key + 提示词 + 触发规则），任意代码托管以后再说（需要容器隔离），并可做成付费；数据库预留配额字段。
- 原生接口与客户端相同；另有 OneBot v11 兼容层，NoneBot2 插件改连接配置即可搬来。

## 9. 表情包（第三阶段）

- 全站共享库，感知哈希去重，显示最早上传者；个人收藏夹多对多引用。
- 搜索：先关键词 + 标签；再用 5060 后台慢慢跑 OCR + CLIP 建索引（pgvector），搜索时只需把搜索词转成向量，CPU 也够。
- 外部搜索源接口预留；外部图片经服务器代理缓存，用户发出时自动收录。

## 10. 社区（第四阶段）

好友动态 / 公开广场；发布选"公开"或"仅好友"；评论也只能划掉；帖子带举报计数和隐藏字段，管理员隐藏留记录。

## 11. 创意工坊（第五阶段）

- 小游戏与功能增强都是网页小程序，跑在沙盒 iframe，只能调平台接口，安装时弹权限清单，网络走白名单代理。
- 提交：开发者把源码放公开 GitHub 仓库，填地址 + 版本标签；服务器拉该 commit 的快照自己打包，审核和安装都绑定该 commit。
- 审核：只收源码（拒收混淆代码）→ AI 审核（对照声明权限读源码）→ 高权限人工复核 → 上架后举报。
- 公示：插件运行需服务器发令牌，资料页由服务器下发已开插件及关键权限；可远程停用。

## 12. 规模化预留

1. 按时间递增的消息 ID。
2. 会话内递增 seq，同步量只和离线时长有关。
3. 存储层隔离（`store` 包）。
4. 连接层（gateway）与业务层分开，模块经 `push.Pusher` 推送。

## 13. 分阶段路线

| 阶段 | 内容 |
| --- | --- |
| 1 聊天核心 | 账号与邀请码、私聊和群聊、文字/图片/文件、划掉、管理员删除、置顶、免打扰、群管理、断线同步；网页版 + Windows 版 |
| 2 安卓与开放接口 | 安卓版 + 推送（UnifiedPush）、Bot API、OneBot v11 兼容层、AI 对话栏 |
| 3 表情包 | 表情包库、收藏夹、关键词搜索、OCR + CLIP、外部搜索源 |
| 4 社区 | 好友动态、公开广场、点赞评论、举报与隐藏 |
| 5 创意工坊 | 沙盒运行时、权限清单、审核、强制公示、远程停用 |

第一阶段分批：
1. **后端核心（已完成）**：协议、账号、邀请码、会话、好友、私聊、发消息、划掉、同步、已读、命令行测试客户端、自动编译。
2. 群聊、群管理、管理员删除、图片和文件上传。
3. 网页客户端界面。
4. Tauri 打包 Windows 版。
5. 置顶、免打扰、未读数等收尾。
