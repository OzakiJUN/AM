# AM 设计文档

> 本文件是设计基准。claude.ai 上的讨论稿只作历史参考，有冲突以这里为准。
> 最后更新：2026-11-01（AI 收尾：申请共用 AI、添加 bot、游戏接口、余额提醒、自己的形象包、语音输入接口）

## 1. 原则

- **协议先行**：消息协议和数据结构先定死、写成文档，再写代码。加功能是加新事件类型，不推翻旧结构。
- **模块边界清楚**：后端是一个程序，内部按模块分包；只有 `store` 碰数据库，只有 `gateway` 维持连接。
- **身份由服务器盖章**：bot / AI 标识、插件公示这类"不能撒谎"的信息，一律由服务器生成，客户端只负责显示。
- **消息只追加，不抹除**：普通用户只能划掉，不能撤回；管理员删除对用户不可见，但服务器保留证据和记录。
- **文档和代码同仓库**：每次开工先读文档，再改对应模块。

暂不考虑：商业化、联邦互通、聊天内容端到端加密。合规义务见第 15 节。

## 2. 已定决策

| 项目 | 决定 |
| --- | --- |
| 开发方式 | 从零自研，不基于 Matrix 等现成框架 |
| 分发模式 | 发布的是软件：带界面的客户端 + 服务器。服务器由用户自己搭，客户端用加入码 / 二维码连接（见第 3 节）。不搭官方大型服务器，不涉及备案 |
| 后端 | Go；数据库默认 SQLite（单文件、免安装），可切换 PostgreSQL；第一阶段不用 Redis |
| 客户端 | React + TypeScript，Tauri 2 打包 Windows / 安卓。不做纯网页版（网页不能信任自签证书）。界面风格参考 NapCatQQ 的客户端，要好看 |
| 客户端更新 | 外壳 + 可热更新的界面包；界面更新不用重装；更新从 GitHub Releases 拉取（以后可加镜像），不经各自建服务器 |
| 创意工坊 | 托管在 GitHub：索引仓库 + 作者仓库的 Release，PR 审核上架，不需要官方服务器；侧载未审核内容需开发者开关，加载时警告并公示（见第 13 节） |
| 协议定义 | Protobuf 一份定义，生成 Go 和 TS 代码；WebSocket 用二进制 protobuf，HTTP 用 protojson |
| 撤回 | 改为"划掉"：删除线 + 标记，原文仍可见，不可撤销 |
| 编辑 | 不提供。发错只能划掉重发 |
| 管理员删除 | 对所有用户消失，原位置留删除记录；内容移入违规证据区保留 6 个月（可配置）后自动清除 |
| 日志留存 | 登录记录（时间、IP、设备）至少保留 6 个月 |
| 实名 | 数据库预留实名字段，现阶段不启用；对外开放前接手机号验证 |
| bot / AI | 不限功能；必须标明 AI 身份和主人 |
| 普通账号挂 AI | 检测标记 → 管理员确认 → 封禁；举报查实直接封 |
| 内容规则 | 鉴政一律封号 |
| 海外模式开关 | 不做。若做国际版，部署为完全独立的一套服务（账号、数据分开），客户端不放切换开关 |
| AI key | 客户端用密码派生的密钥加密后存服务器，登录时下载，客户端直接调用 |
| 服务器形态 | 类似 Discord：一个自建服务器 = 一个社区。没有好友：服务器里的人都能直接私信，可以屏蔽；群改叫"频道"，分公开（所有人，自动加入）和私密（邀请才能进）（见第 8 节） |
| 注册方式 | 邀请码注册。每个账号注册后自动获得 3 个邀请码（可配置），在客户端里以加入码 / 二维码发给朋友；管理面板不生成邀请码，只能查看和作废。第一个账号用服务器窗口里的管理员加入码注册，成为站点管理员 |
| 全员禁言 | 不做 |
| 外部表情包搜索 | 预留"搜索源"接口，暂不实现（Tenor API 已于 2026-06-30 关停） |
| 部署（第一阶段） | 13600 + 阿里云 5M frp 中转，不用域名，客户端直连 IP + 端口，自签证书 + 指纹固定 |
| 大规模后的媒体 | 预留：媒体访问都走 media 模块，自建服务器以后想换对象存储只改这一处。现阶段不做 |

## 3. 分发与自建

- 发布到 GitHub 的是工具：客户端（Windows / 安卓）和服务器 `am-server`。每个人可以自己搭服务器，邀请朋友来用。各服务器上的内容由搭建者自己负责。
- **服务器**：一个文件 `am-server.exe`，双击就跑：不弹黑框，任务栏右下角有托盘图标，自动在**独立窗口**里打开管理面板（WebView2，Win10/11 自带；没有时退回浏览器）。窗口是单独的 am-server 子进程（`window` 命令），关掉窗口服务器照样在托盘运行，窗口出问题也不会拖垮服务器。第一次启动自动生成配置、数据库（SQLite）、证书和管理员加入码。再双击一次不会开第二个，只会把窗口调出来。
  - 管理面板是 am-server 内嵌的网页（`server/internal/admin`，纯 JS，无构建步骤），默认只监听 `127.0.0.1:8444`。登录用 `data/admin_key.txt` 里的密钥，托盘图标打开时自动登录。功能：概览（首次：管理员加入码 + 二维码；之后：服务器码，用于已有账号在新设备上添加服务器）、用户（封禁 / 解封、重置密码、设管理员、登录记录）、邀请码（查看谁邀请了谁、作废）、频道记录（所有频道的聊天记录，公开和私密都有，只读；**私信看不到**，面板取图片也只给频道里的、头像和证据区的；打开某个频道写一条审计日志）、删除记录（证据区）、操作记录（审计日志）、运行日志、设置（表单 + 直接编辑 config.toml，保存前校验，旧版本存 .bak；另有「服务器主页」：图标、简介、谁能改布局、成员能不能改小组件内容，存在数据库里，立即生效）、开机自启、重启 / 退出。
  - 聊天服务在可重启的循环里运行（`supervisor`），面板一直在线：配置写错或端口被占时面板显示原因，改好设置点重试即可，不用碰命令行。
  - Linux 云服务器用同一份代码（`-headless`，无托盘、不开浏览器），面板通过 SSH 隧道访问。
  - 配置里的相对路径（`data_dir` 等）以配置文件所在文件夹为准；Windows 下默认配置文件在 exe 旁边。
- **加入码**：服务器地址、端口、证书指纹（前 16 字节）和邀请码打包加扰成一串 `AM1-XXXX-...`，不明文露出 IP（只是防一般人看到，不算保密：客户端要能解开才能连）。不带邀请码的叫"服务器码"，用于已有账号在新设备上添加服务器。格式见 protocol.md。
  - 二维码内容是 `<下载页>#join=<加入码>`：别的软件扫码打开客户端下载页（默认 GitHub Releases，`invites.download_url` 可改），AM 客户端扫码直接读出加入码进入注册页。
  - 服务器知道公网地址（`server.public_address`）时，邀请码列表里直接带加入码；不知道时客户端用自己连接的地址拼出来。
  - 客户端可保存多个服务器。同一个地址换了证书（服务器重装过），加入时先问一句「这个地址以前是『XX』，证书变了，要替换吗」，确认后换成新证书，旧的登录状态作废（以前是直接替换，看起来像旧服务器消失了）。
- **图标**：客户端和服务器同一个可爱的气泡脸，颜色不同好区分：客户端是应用里的樱粉→薰衣草渐变，服务器是薄荷→海盐蓝并带一个服务器小角标（托盘 16 像素也能分清）。所有尺寸由 `scripts/icons/make_icons.py` 生成，改图就改脚本重跑。
- **自签证书与客户端**：浏览器和 WebView 不能按指纹信任自签证书，所以 Tauri 客户端的联网由程序本体（Tauri 的 Rust 部分）负责，按加入码里的指纹校验，界面通过 IPC 调用。因此不做纯网页版客户端。
- **协议版本**：服务器和客户端互报协议版本；客户端太旧时提示更新。
- **更换中转地址**（已完成）：管理面板概览页的「中转地址」。先把新中转的 frp 配好，填新地址 →「检查」：am-server 通过新地址连自己，证书（自签时）和进程 id（`ServerInfo.instance_id`）都对得上才算通 →「更换并通知客户端」：写进 config.toml（`server.public_address`），不用重启，旧地址记在 `server_settings`（最多 5 个），给所有在线连接推 `server_moved`。
  - 客户端收到后先用同一个证书指纹连新地址，连上了才切过去（登录不变），旧地址记在本机（`oldAddresses`）；连不上就继续用旧的。当时不在线的客户端下次从旧地址连进来，登录回复里的 `public_address` 会让它切过去。当前地址连续连不上时，客户端自动试以前的地址。
  - 客户端登录时报告自己连的是哪个地址（`AuthRequest.address`），面板显示「还在用旧地址的设备」，等它变成 0 再关旧中转。旧中转关掉以后一直没上线的设备，只能重新给它服务器码：粘贴同一个服务器（证书相同）的新码会直接更新地址、保留登录。
  - 我的多台设备之间同步服务器列表时，服务器按证书指纹认（不按地址），所以换地址不会被当成「退出了一个、加入了一个」；别的设备看到新地址也会去检查并切换。
- **更新**（Weiqi 定的，AI 功能做好、给朋友试之前完成）：
  - 服务器先更新：am-server 定期查 GitHub Releases，管理面板提示有新版，一键（或按配置定时自动）下载、验签、替换、重启。同时把对应的客户端安装包存一份。
  - 服务器更新完向在线客户端推「有新版客户端」（之后连上的也会收到）。
  - 客户端先从 GitHub 下载，下不动再从服务器存的那份下载；装之前用内置公钥验签，所以经过谁转发都改不了安装包。服务器自己的更新包同样验签。
  - 客户端自己也定期查 GitHub 兜底（服主不更新服务器时也能收到）。连着多个服务器时哪个先通知用哪个；协议只加字段，新旧版本混用没问题。
- **创意工坊**：官方运营的独立服务（`am-workshop`），是唯一连到官方服务器的部分。
  - 创作者用 GitHub 账号登录、从 GitHub 仓库提交；浏览和下载不需要账号。
  - 审核通过的内容由工坊私钥签名，客户端 / 服务器内置公钥验签，验签通过才算"已审核"。
  - **侧载**：开发者可在客户端打开"开发者模式"加载本地未审核内容，加载时弹警告，个人资料页公示"侧载（未审核）"。每个服务器的管理员可在配置里禁用侧载。
  - 工坊是官方公开分发用户上传内容的平台，审核责任在官方，必须严格审核。

## 4. 架构

```
客户端（Windows / 安卓 / Bot 程序）
   │ WebSocket（实时）        │ HTTP（登录、成员、上传等）
   ▼                          ▼
┌──────────── am-server（Go，单个可执行文件）────────────┐
│ supervisor：可重启的服务循环   admin：管理面板（仅本机）  desktop：托盘 │
│ gateway：连接与推送        httpapi：HTTP 接口          │
│ account │ conv │ message │（后续：media admin bot ai sticker community workshop）│
│ store：唯一读写数据库的模块                              │
└─────────────────────────────────────────────────────────┘
   ▼
SQLite 或 PostgreSQL ／ 文件存储 ／ 违规证据区
AI 服务商 ← 客户端直连（不经服务器）
官方创意工坊 ← 客户端只在浏览 / 下载工坊内容时连接
```

## 5. 客户端

**技术栈**：Tauri 2（Rust 外壳）+ React 19 + TypeScript + Vite + Tailwind CSS 4 + motion（动画）+ zustand（状态）。界面组件自己写（`client/src/ui`），不依赖组件库。代码在 `client/`，界面在 `client/src`，外壳在 `client/src-tauri`。先做 Windows，安卓以后用同一份代码（Tauri 2 支持安卓）。苹果不做（上架和签名要每年 99 美元的开发者账号）。

**联网**

- 桌面版里所有请求都由 Rust 部分发出（`src-tauri/src/net.rs`：reqwest + rustls + tokio-tungstenite），按加入码里的证书指纹校验自签证书；没有指纹（正式证书）时按系统根证书校验。界面通过 Tauri 命令调用（`api` / `upload` / `download` / `ws_open` ...），WebSocket 帧经 Channel 传回界面。
- 图片、头像等媒体走自定义协议 `ammedia://`，由 Rust 带上登录令牌去服务器取，界面直接 `<img src>`。
- 浏览器开发模式（`npm run dev`）没有 Rust 部分：Vite 把 `/api`、`/ws` 代理到本机一个关掉 TLS 的 am-server。只用于开发和自动化测试，不是网页版。
- 协议代码由 `buf generate` 生成到 `client/src/gen`（protoc-gen-es），HTTP 用 protojson，WebSocket 用二进制 protobuf，和服务器同一份 proto。

**功能（第 4 批）**：多服务器（会话列表顶部切换）；加入码 / 二维码注册登录，启动时读剪贴板，发现加入码直接提示；频道（公开 / 私密）和私信、文字 / 表情 / 图片 / 文件（粘贴、拖拽）；划掉、管理员删除；频道成员管理和加入审批；服务器成员列表、屏蔽；个人资料、个性签名、邀请码（加入码 + 二维码）、登录设备和登录记录；在线状态、隐身和"正在听歌"之类的状态（第 7 节）；断线自动重连并补消息；窗口不在前台或正在看其他会话时弹系统通知。Windows 便携版与安装版使用相同的 AM 通知身份，在当前用户下注册；只有当前会话所在窗口可见、未最小化且有焦点时才略过提醒。设置 → 通知与窗口可发送测试通知。

**界面风格**：参考 NapCatQQ 客户端——渐变背景 + 模糊光斑、近白色卡片、圆角。阴影浅而大、四周都有、没有硬边；鼠标移上去卡片抬高、阴影扩大，按下压低；动画全部用非线性曲线（ease-out / 弹簧），页面、弹窗、菜单、导航指示条都有过渡。

**防重复点击**：凡是要等服务器的操作，对应按钮 / 开关 / 菜单项在请求完成前显示加载并且不能再点。做在组件里（按钮的 onClick 返回 Promise 就自动进入加载状态；确认弹窗的"确定"等操作完成再关；菜单项同一操作进行中不重复执行），新加的按钮自动具备。

**服务器列表**：会话列表顶上的服务器信息点开是服务器列表：点名字切换，点头像打开那个服务器的主页（第 8 节），最下面是「加入新服务器」。加入界面有「先不加入，进入主界面」，没有服务器时主界面提示去加入。

**导航**：最左边一栏是总导航——频道、私信、AI、创意工坊（现在只有占位页：暂不可用、排在第五阶段、以后会有什么），以后加社区；底部从上到下是账号设置（小人图标）、设置、自己的头像。
- 账号设置：改昵称、头像（支持 GIF）、个性签名，我的邀请，登录设备，登录记录，退出登录。
- 点头像打开个人主页（第 7 节）：大卡片（会动的头像、名字、状态、签名）、主页小组件（第 7 节）。个人主页只用来看；昵称、头像、签名、我的状态（隐身、正在做什么）都在账号设置里改。
- 头像右上角的状态点：在线时绿点里显示正在做什么的 emoji（🎧 🎮 🛠️ 📚 💬），没设就是白对勾；隐身是灰色空心圈（只有自己和自己的 AI 看得到）；离线灰点。头像小于 28 像素时只显示纯色点（放不下）。
- 左边的会话列表（频道 / 私信 / AI 三页共用一个开关）和右边的频道成员列表都能收起，收起后只留一列头像：会话头像带未读数，成员头像右上角是在线状态点（在线绿点、离线灰点、自己隐身时是空心圈），鼠标移上去显示名字。收起的会话列表里，切换服务器和新建频道这些操作收在顶上一个按钮里。宽度用弹簧动画变化，收起状态存在本机。
- 频道页：左边是这个服务器里你加入的频道（私密频道带锁），上面有"浏览公开频道"和"新建频道"。有人加入 / 退出 / 被移出 / 改角色时，服务器只把新的频道信息推给那个人，其他成员的客户端看到这条系统消息就重新取一次频道（同一频道 0.3 秒内合并成一次），成员列表马上更新。
- 私信页：左边是私信列表，上面有"服务器成员"，搜到人直接私信。
- 和 bot / AI 账号的私信不放在私信页，统一放在 AI 栏（见第 9 节）。
- 设置里有"隐私"：屏蔽的人列表。

**个性化**（只存在本机）：浅色 / 深色 / 跟随系统；主题色（6 个预设 + 自定义颜色）；导入背景图片（可调模糊和遮罩）；面板样式（磨砂 / 清透 / 染色（带一点主题色）/ 不透明）、面板透明度（20%–100% 不透明）和面板模糊（0–40 像素），导入自己的背景后既能看到背景，字也看得清；字体大小。以后创意工坊的"主题"可以一键套用这些设置（见第 13 节）。
- 颜色都用自己的取色器（`ui/ColorPicker.tsx`，颜色计算在 `lib/color.ts`）：饱和度 / 亮度方块、色相条、颜色代码、屏幕取色（WebView2 有 EyeDropper 时）、预设色和最近用过的颜色；浮在按钮旁边的玻璃面板里，点外面或按 Esc 关闭，改动实时生效。不再弹系统取色器。

**窗口**：点关闭按钮默认收到托盘（右下角图标，单击打开、右键菜单「打开 AM / 退出」），这样 AM 继续收消息，在这台设备上运行的 AI 也保持在线；设置 → 通知与窗口里可以改成直接退出。

**更新**

- 客户端分两层：**外壳**（Tauri 程序本体，提供窗口、通知、文件、联网等底层能力，很少变）和**界面包**（网页代码，经常变）。
- 界面包：客户端启动时从发布渠道（GitHub Releases，以后可加镜像）查询最新版本，后台下载，下次启动生效。界面包必须带签名（发布时用私钥签，客户端内置公钥验签），验签失败不加载，回退到上一个版本。
- 外壳：底层功能变化时才更新，用 Tauri 官方自动更新插件，同样验签，点一下重启即完成。
- 界面包声明它需要的最低外壳版本；外壳太旧时提示先更新外壳。

## 6. 消息模型

会话里的一切都是事件（`am.v1.Event`），只追加：

- `event_id`：64 位按时间递增的全局 ID（雪花算法）。
- `seq`：会话内从 1 开始、无空缺的序号。断线重连按 seq 补缺。
- `client_msg_id`：客户端生成的去重 ID，网络重发不会产生两条；只回给发送者本人。
- 事件体是 oneof：文字、图片、文件、划掉、管理员删除、成员变动、会话信息变动。

**规则**

- 划掉：只能划自己的文字 / 图片 / 文件消息，随时可划，每条只能划一次，不可撤销。
- 管理员删除：
  - 对用户：目标事件的正文不再下发，事件带 `redaction`（删除者、原因、时间），另追加一条 `admin_delete` 事件。
  - 对服务器：正文和文件移入违规证据区（只有站点管理员可查看），保留期满自动清除；删除动作写审计日志；图片感知哈希进黑名单。
- 普通用户没有任何删除接口。
- 未读数 = 会话 last_seq − 自己的 read_seq。

## 7. 账号与身份

| 类型 | 创建方式 | 显示 |
| --- | --- | --- |
| human | 邀请码注册 | 正常 |
| bot | 主人在"我的 bot"里创建 | 「Bot · 主人：xx」 |
| ai | 同上，选 AI 类型；私人 AI 拉进群也是这类 | 「AI · 主人：xx」 |

- bot / ai 没有密码，只能用主人生成的 token；主人被封，名下 bot 一起停用。
- 密码 Argon2id；每台设备一个会话 token（服务器只存 SHA-256），可逐个踢下线，踢掉立即断开连接。
- 登录记录（时间、IP、设备名）单独存表，保留 6 个月以上。

**一个我，多个服务器（资料同步）**

- 每个自建服务器各有自己的账号（服务器之间不互通，也没有中心服务器）。「同一个账号」由**客户端**带过去：设备就代表本人，不做切换账号。
- **保存的登录**：第一次登录 / 注册成功后，用户名存在本地，密码交给系统的凭据管理器（Windows 凭据管理器，`client/src-tauri/src/secrets.rs`；浏览器开发模式下放 localStorage，只用于开发）。之后加入新服务器、登录失效重新登录时不用再输；可以「换一个」临时用别的密码。只保存第一次的那一组，在账号设置里「忘记」后下次登录再存。
- **加入新服务器时「用我的资料」**（默认开）：用户名和密码用保存的，注册后把昵称、头像、签名、隐身 / 正在做什么、个人主页（小组件和背景，图片重新上传一份）从当前服务器复制过去。用户名被占了就改一个。
- **一直同步**（默认开，账号设置里可关）：在任何一个服务器上改了上面这些，等一段时间（默认 30 秒，可选 10 秒 / 30 秒 / 2 分钟 / 10 分钟，每次改动重新计时）后复制到其他所有服务器，同一项以最新的改动为准。要同步的内容记在本机，对方服务器离线时等它连上再同步；网络 / 服务器忙之类的失败 2 分钟后重试，对方拒绝的（比如内容不合规则）放弃并在账号设置里显示原因。账号设置里有「把这里的资料同步到其他服务器」手动推一次。
- **表情也同步**（2026-11-01，Weiqi：「每个人带进新服务器里的表情，在后台限速慢慢传到服务器里」）：我在任何一个服务器上有的表情，客户端在后台一张一张复制到我的其他服务器（加入新服务器后也会把以前的全带过去）。先问对方服务器公共库里有没有这个文件（`/api/v1/sticker-library/lookup`），有就直接收藏不用传；没有才下载再上传，接收服务器按实际读取的字节限速。所有后台同步上传共用 config.toml 的 stickers.sync_kbps（默认 64 KiB/s，0 为不限），普通聊天上传独立，免得占满中转的带宽。公开 / 不公开、标签跟着走。新加的表情等 2 分钟再复制（留时间填标签、改成不公开）；复制过以后在原服务器改成不公开，复制出去的那些也会改成不公开（2026-11-01 修：以前刚导入就可能被复制成公开的）。删掉的不跟着删；复制过的记在这台设备上，别处删掉的不会再补回去。对方满了（`sticker_limit`）就停下并在账号设置里显示原因；图被拉黑 / 太大的跳过；网络问题 2 分钟后再试；另外每 15 分钟、有服务器连上、自己加了表情时都会检查一次。账号设置「资料同步」里可以单独关掉「表情也同步」。代码 `lib/stickerSync.ts`，计划部分 `lib/stickerCopy.ts`（纯函数有单测）。
- 不同步：聊天记录、频道、留言板的留言、统计数字（这些属于各自服务器）。
- 资料同步由改资料的那台设备来做（它记着要同步什么）。别的设备直接从服务器读到新资料。两台设备同时改，以各自最后同步的为准。
- 图片按「来源服务器 + 图片 id → 目标服务器上的 id」记在本机，没变的图片不重复上传；服务器重装过（证书变了）就把它相关的记录清掉，避免 id 撞车拿错图。
- 代码：`client/src/lib/profileSync.ts`（复制逻辑，可单测）、`lib/sync.ts`（排队、计时、接到各服务器会话上）、`lib/identity.ts`（保存的登录）。

**个人资料**

- 个性签名：最多 100 字，在账号设置里改，显示在个人主页上。
- 头像支持 GIF（以后可服务器转码为体积更小的动图格式）。列表、聊天里显示静态首帧，进入个人主页才播放动画，避免占满带宽。
- 个人主页：大卡片（会动的头像、名字、签名、在线状态），下面是**小组件**。只用来看，改资料和状态在账号设置。点聊天里别人的头像、或成员列表里的「查看主页」能看别人的主页（只读，可以留言、发私信）。

**主页小组件**（个人主页和服务器主页共用一套）

- 像手机桌面：最多 3 页，每页横屏（电脑）8 列 × 4 行、竖屏（手机）4 列 × 8 行。小组件 1×1 到 4×4，可以放在任意格子、允许留空。看别人主页时空白页不显示，左右滑或点圆点翻页。
- 横竖屏各一份布局：电脑上摆横屏版，竖屏版自动按「页 → 行 → 列」的顺序依次排；在竖屏下手动挪过以后就按手动的来（可以一键「竖屏重新自动排」）。不做整体旋转（2×1 会变成 1×2，内容会挤坏）。
- 布局存成 JSON（proto `ProfileLayout`）：每个组件的 ID、类型、来源（内置 / 工坊）、尺寸、两种方向的位置、内容配置（JSON，最多 8 KB）；外加主页背景（默认 / 渐变预设 / 纯色 / 图片，可调模糊和变暗）。
- 内置组件：文字卡片、图片、照片墙（多张自动轮播）、链接（最多 6 个，点开前确认）、倒计时、统计、留言板、一首歌、歌单、我的状态（个人主页）、在线成员（服务器主页）。
  - 统计：个人——发过多少消息、连续在线几天（服务器每天记一次谁连上过，从这批开始算）、加入服务器多久；服务器——成员、消息总数、频道数、开服多少天。显示哪几项可以选。
  - 一首歌 / 歌单（Weiqi：不要网易云的播放器组件，自己做界面；歌可以是网易云的）：每首歌要么是网易云的歌，要么是上传的文件，编辑时选「网易云链接 / 上传文件」。
    - 网易云：贴单曲或歌单的分享链接（整段分享文字、163cn.tv 短链都行），AM 服务器去读（`server/internal/music`，`POST /api/v1/music/resolve`）：歌名、歌手、歌单里前 50 首；封面下载下来存成主人的上传，访客从 AM 服务器看封面，不连网易云。读的是网易云网页自己用的 JSON 接口（`/api/song/detail`、`/api/v6/playlist/detail`），不是公开 API，哪天变了就读不到（`music_unavailable`），已经放上去的歌不受影响。配置 `media.netease`（开关）、`media.netease_api`（地址，测试指向假服务）。
    - 播放网易云的歌：听的人点播放后，他自己的客户端从网易云的外链地址（`music.163.com/song/media/outer/url?id=…`）取，不经过 AM 服务器（中转只有 5M，扛不住）。会员 / 版权歌曲网易云不给外链（跳到它的 404 页），会提示放不了。
      - 桌面版（2026-11-01 改，Weiqi 测试时网易云的歌都「播放失败」）：播放器加载 `ammusic://localhost/<歌曲 id>`，由 Rust（`src-tauri/src/music.rs`）带上网易云要的请求头（浏览器 UA、Referer music.163.com）去取，跟着它跳到 CDN（可能是 http 的 m*.music.126.net），整首放在内存里（最近 3 首，最大 60 MB），按 Range 分段给播放器，所以能拖进度条、不受页面 CSP 和防盗链影响。浏览器开发模式还是直接用外链地址。
    - 上传：歌是主人上传到服务器的音频文件（mp3、m4a、flac、ogg、wav…，服务器按内容或文件名认，`media.IsAudio`），看主页的人都能听，跟主页图片一样由主页引用保住不被清理。「一首歌」（2026-11-01 Weiqi 定的新样子）：封面铺满整个小组件（裁切不变形，没封面就是主题色渐变），上面一行是歌名 - 歌手（放不下时来回滚动，两头停一下），正中是白色的播放 / 暂停图标（没有底色），下面是进度条（可点）；编辑时可以选「封面模糊一点」（`config.blur`）。「歌单」：歌单名、封面、最多 50 首（网易云和上传的可以混着放）（一次可以选好几首，文件名「歌手 - 歌名」自动分开，能排序），点哪首放哪首，上一首 / 下一首，放完一首接下一首。设置 → 声音可调本机音乐音量（0–100%，默认 30%），播放中立即生效并记住。整个客户端只有一个播放器（`lib/player.ts`），放一首别的就停。桌面版的媒体走 `ammedia://`，不支持按范围取，拖进度条要等整首下载完。资料同步时歌也一起复制到别的服务器。
  - 网易云歌单（旧）：已经放了的照常显示（外链播放器，点一下才加载），添加列表里不再出现。
  - 留言板：每条最多 200 字，一分钟最多 3 条，屏蔽了对方就不能留言。不能删也不能改自己的留言；主页主人可以隐藏某条（只有主人和管理员还看得到）；站点管理员可以删除，原文作为证据保留 `retention.evidence_days` 天后清除。
- 编辑：点「编辑主页」，组件轻微晃动，拖动换位置（目标格子绿色能放、红色不能放），⚙ 改内容 / 大小 / 第几页，✕ 删除，「添加」从组件列表里加，「背景」改背景。可以切换横屏 / 竖屏预览。全部改完一次保存。
- 每次保存都是新版本（只追加）：最新的是当前布局，旧版本作为证据 / 可回退，保留 `retention.evidence_days` 天后清除。保存时带上编辑开始时的版本号，期间有人存过就提示刷新（多人改服务器主页时）。
- 权限由服务器逐项检查：个人主页只有本人能改；服务器主页见第 8 节。组件里的图片必须是改的人自己上传的，所有人都能看。管理面板用户列表有「清空主页」（违规内容，写审计日志）。
- 主页不实时推送更新：打开时取最新的，有刷新按钮。
- 工坊组件在第五阶段（第 13 节），布局格式已经留好位置。

**多设备**

- 一个真人账号最多同时登录 `limits.max_devices` 台设备（默认 3，电脑手机不分；管理面板可改，0 不限）。满了以后用密码登录、生成登录码、用登录码都会被拒（`too_many_devices`），要先在一台设备上退出或让它下线。bot / AI 账号不算，它们是单独的账号。
- 登录记录照常写（`kind = pair` 表示用登录码登录的）。设备丢了又没有别的设备能让它下线：找管理员在面板里重置密码，所有设备一起下线。
- 客户端「退出登录」会通知服务器删掉这台设备（`POST /api/v1/logout`），名额马上空出来。
- **添加新设备**（账号设置 → 登录设备）：旧设备在每个登录着的服务器上要一张一次性 ticket，把服务器列表、其他服务器的 ticket、保存的用户名密码、共享密钥、个性化设置（主题、颜色、背景、字号、各种偏好）打成一个包，用新生成的密钥加密后存到当前服务器（跟当前服务器的 ticket 放在一起）。界面显示登录码（`AMP-...`，文字 + 二维码，格式见 protocol.md），`limits.pair_code_minutes` 分钟（默认 5）内有效，只能用一次。
- 新设备：欢迎页「从已有设备登录」（或在剪贴板 / 二维码里认出登录码），用 ticket 登录当前服务器、取回包、解密，再用包里的 ticket 登录其他服务器；没拿到 ticket 的（当时连不上、设备满了）用保存的密码登录，还不行就留到之后在登录页输密码。旧设备上的对话框看到多了一台设备就显示「新设备已登录」。
- 包和共享数据都是端到端加密的：密钥只在登录码 / 我的设备里，服务器（和它的管理员）看不到我还在哪些别的服务器上，也看不到密码。背景图片太大（包超过 32 KiB）就不带，提示在新设备上重新选。
- 不加「新设备显示数字、旧设备确认」这一步（Weiqi 定的）：靠一次性、5 分钟过期、登录后提醒、能马上让它下线。
- **我的服务器列表跨设备同步**：每个服务器上存一份加密的「我的服务器列表」（`/api/v1/me/client-state`，用共享密钥加密，前 4 字节是密钥指纹）。每个服务器是一条记录（地址 + 证书 + 名字 + 改动时间，删掉的留个标记），合并时每条取新的（`client/src/lib/deviceState.ts`，纯逻辑有单测）。
  - 在一台设备上加入新服务器（登录成功）或退出 / 去掉一个服务器，会把列表合并后存到我所有在线的服务器上；服务器给我其他在线的设备推 `client_state`，它们马上取回合并。设备连上服务器时也取一次。
  - 别的设备上新加的服务器：服务器列表里多一栏「你在另一台设备上加入了」，点「加入」用保存的密码登录（不行就到登录页输密码），也可以「忽略」（只在这台设备上记着）。
  - 别的设备上退出的服务器：这台设备也去掉（如果是在这台设备加上它之后才退出的）。
  - 共享密钥第一次用到时生成，存在系统凭据管理器里，靠登录码带到新设备。从来没有配对过的两台设备密钥不同，互相看不懂对方存的列表：遇到看不懂的就不动它。
  - 代码：`client/src/lib/devices.ts`（配对、列表同步）、`lib/paircode.ts`（登录码和加密）。服务器端 `server/internal/account/devices.go`，表 `pair_tickets`（过期的由 janitor 清掉）、`client_states`（退出服务器时删除）。

**在线状态**

- 有设备连着就是在线。服务器把每个人的在线状态推给服务器上所有在线的人（自建服务器人少，全推没问题），客户端在成员列表、私信列表、私信标题里显示。
- **隐身**：别人看到你是离线的。但你自己的 bot / AI 账号能看到你其实在线（带"隐身中"标记）——AI 知道主人在，可能在聊天里说漏嘴，这是故意留的"暴露的可能"，不是彻底隐身。
- **正在做什么**：正在听歌、正在打游戏、正在调试 AI、学习 / 工作中、自定义，可以附一句话（最多 32 字，如歌名、游戏名；自定义必须写）。只在在线时显示。现在是手动设置，以后可以由客户端自动识别（正在播放的歌、正在运行的游戏）。
- 隐身和状态存在服务器上，换设备、重启都还在。
- AI 栏的立绘用 AI 账号自己的在线状态：AI 没连上就显示 `offline`（回不了话）。

## 8. 频道与私信

自建服务器本身就是一个小圈子（靠邀请码进来），所以不做好友：和 Discord 一样，服务器里的人都能找到彼此、直接私信。

- **服务器主页**：和个人主页同一个思路——大卡片（服务器图标、名字、简介、成员数、在线人数）+ 小组件网格。站点管理员在管理面板里设置图标、简介和两项权限：
  - 谁能改布局（摆放、增删小组件）：仅管理员 / 所有人；
  - 成员能不能改小组件内容（只改内容，不能改类型和位置）。打开后，站点管理员可以在每个小组件的 ⚙ 里设成「只有管理员能改」。
  - 站点管理员什么都能改；服务器主页的每次保存写审计日志。
- **退出服务器**：服务器主页右上角。在服务器上标记为"已退出"：所有设备登出、退出所有频道（自己是频道主的交给下一个人——角色最高、进来最早的；没有别人的频道解散）、成员列表里看不到、不能被私信或拉进频道。账号和发过的消息都还在。要回来必须有新的邀请码：用带邀请码的加入码登录原账号即可（邀请码被用掉），回来后自动加入公开频道。退出最后一个服务器后回到加入界面。
- **私信**：两人会话，服务器上任何人之间都能发起；同一对用户只有一个私信。
- **屏蔽**：屏蔽后双方都不能再发私信（以前的消息还在，划掉自己的消息仍可以），频道里不受影响。屏蔽列表在 设置 → 隐私。
- **频道**（协议里叫 group）：频道主 / 管理员 / 成员。
  - 公开频道：服务器上所有人都能看到和加入，新注册的人自动加入所有公开频道；只有站点管理员（服主）能建。退出后可以在"浏览公开频道"里再加回去。
  - 私密频道：就是原来的群，邀请才能进，任何人都能建。成员可以拉服务器里任何人（开了加入审批时要管理员同意）。
  - 第一个管理员账号注册时，服务器自动建一个公开频道（配置 `server.default_channel`，默认"大厅"，留空不建），新服务器不会空着。升级前已有的群都变成私密频道。
  - 管理员可改频道信息、踢人、禁言成员（不能动管理员）、删除他人消息（留记录）、加入审批；频道主额外可设管理员、转让、解散。
  - 第二阶段加"添加 bot"，只能添加自己的 bot。
- **先不做**：频道分组、语音频道、帖子 / 子话题。
- **置顶 / 免打扰**（频道和私信都行，右键会话）：是我自己的设置，存在服务器上（`conv_members.pinned_order` / `dnd_until`），我的几台设备都一样（改了推 `conv` 给我所有连接）。
  - 置顶的排在列表最上面，后置顶的在上；以后需要再加拖动排序。
  - 免打扰：1 小时 / 8 小时 / 一直到我关掉。期间不弹通知，未读数变灰，也不算进导航栏和服务器列表的红点。到期自动失效。
- 以后再做：备注。

## 9. AI 对话栏（第二阶段）

**接入**

- 适配器：一个 OpenAI 兼容通用适配器（DeepSeek、xAI、OpenRouter 等），Claude、Gemini 各一个原生适配器。新增服务商 = 新增一个适配器文件。
- 余额（已做）：能查的服务商在「模型服务商」里每行显示余额，有「刷新」和「去充值」（跳官方充值页）。低于这个服务商设的数（默认 5，单位跟着服务商的币种，0 = 不提醒）时提醒主人，同一个服务商 6 小时最多提醒一次；开软件 20 秒后查一次，之后每 3 小时查一次。代充 / 转售暂不做。
  - 现在能查的：DeepSeek（`GET https://api.deepseek.com/user/balance`，普通 key 就行，返回各币种余额）；OpenRouter（`GET https://openrouter.ai/api/v1/credits`，剩余 = total_credits − total_usage，**要管理用的 key**，普通 key 会 403，界面上会说）。别家没有公开的余额接口，不显示。
  - 查询也走 Rust（`ai_get`，正常 CA 校验）；解析是纯函数（`providers.ts` 的 `balanceQuery` / `parseBalance`，有单测），提醒在 `lib/ai/balance.ts`。
- key（Weiqi 定的）：服务商列表（名字、类型、地址）存本机，每个 key 单独存在系统凭据管理器里（Windows 凭据管理器每条有大小上限）。整份列表连同 key 放进多设备那份端到端加密的共享数据（第 7 节「多设备」），同步到我的其他设备；服务器看不到。（原来「登录密码派生密钥加密上传」的方案作废。）
- 请求：桌面版从 Rust 发（`src-tauri/src/ai_http.rs`，正常 CA 校验，只允许 https，本机模型可以用 http://localhost），回复按块流回界面；不受浏览器跨域限制。代码：`client/src/lib/ai/providers.ts`（三种接口的请求和流式解析，纯函数有单测）。
- 服务商管理：AI 栏顶上的钥匙按钮。常用的有预设（DeepSeek、OpenAI、OpenRouter、Claude、Gemini、本机 Ollama 等），可以「测试」一下 key 和模型能不能用。

**AI 账号和运行**（第 1 批，已完成）

- 在 AI 栏点「新建 AI」：起名字、选一个起始人格模板。服务器建一个 ai 类型账号，主人是我（`POST /api/v1/ai`，每人最多 `limits.max_ai_per_user` 个，默认 5）。AI 不占主人的设备名额，也不会自动进公开频道。主人被封或退出，AI 一起停。
- **只在一台设备上运行**（Weiqi 定的）：设置里记着运行设备（`settings.runner`，设备 id 在 `lib/deviceId.ts`）。那台设备以 AI 的身份登录（`POST /api/v1/ai/{id}/run`，会结束这个 AI 在别处的登录，所以不会回两遍），token 存在凭据管理器里。设置 → 运行 →「在这台设备上运行」可以换设备。运行设备关着时 AI 离线，立绘显示 `offline`。
- 运行逻辑在 `client/src/lib/ai/runner.ts`：收到私信 → 取最近 N 条（设置里改）+ 人格拼成上下文 → 用主人选的服务商和模型流式生成 → 在运行设备的聊天里实时显示「正在输入」和已经写出来的字，立绘切到 `typing` → 写完后作为 AI 的消息发出，带上情绪（`TextMsg.mood`）。出错时主人的聊天里显示原因和「打开设置」。
- 谁能和它聊：只有我（默认）/ 服务器里所有人（私信）。频道见下面「频道和作息」：在频道里谁都能和它说话。
- 第一次运行时用人格里的开场白跟主人打招呼。
- 设置（人格、模型、温度、记几条、每条最长、谁能聊、运行设备、自己维护人格）是一份 JSON，存在服务器上只有主人能读写（`/api/v1/ai/{id}/settings`），我的每台设备都一样。资料（名字、头像、签名）用 `PATCH /api/v1/ai/{id}`，头像用主人上传的图。
- 删除 AI：AI 聊天顶栏的垃圾桶按钮（自己的 AI 不显示「屏蔽」），或设置 → 运行。退出所有频道、不能再聊，以前的消息还在；`User.gone`（离开、被封、被删）为真的 bot / AI 私信从列表里消失。
- 名字：系统提示第一句就是「你叫 X（主人给你起的名字）」；主人在设置里改名后马上刷新运行中的 AI，不用再告诉它。
- 主页：AI 的个人主页（小组件）由主人编辑（服务器上 bot / AI 的主页编辑权给它的主人）。入口：AI 设置 → 资料 →「编辑它的主页」，或者在它的主页上点「编辑主页」。

**AI 栏界面**

- 三栏：总导航 | AI 列表 | 聊天。AI 列表分"我的 AI"和"添加的 AI"（别人的，标明主人是谁）。和 bot / AI 账号的私信都在这里，不在私信页；从成员列表或频道成员里点 bot 的"发私信"也会跳到这里。
- 聊天窗口和普通聊天大体一样（文字、表情、上传文件、语音输入），但上半部分是 AI 立绘。
- 立绘就是挂在正常聊天界面上面：不另画底色或分隔区域，消息列表照常占满整个高度，往上滚的消息从立绘后面经过（人物周围镂空的地方能看到消息）。立绘不接收鼠标，下面的消息照样能点、能右键。外圈有一层沿着人物轮廓的羽化光晕（浅色模式偏白，深色模式偏主题色），边缘不生硬。
- 立绘位置可选：靠左 / 居中 / 靠右 / 收起到右上角（变成标题栏里的小圆头像，点一下展开）。在标题栏的「立绘位置」按钮里切换，设置 → 外观里也能改，存在本机。移动和收起用弹簧动画。
- 在这里发表情包，AI 收到的只是表情包的标签（表情包库带关键词 / 标签，见第 11 节），不传图片。
- 情绪标签：回复里的 `[mood:xxx]` 最好在开头，但模型常常放在末尾、用全角括号（【mood：开心】）、写中文或近义词（excited、害羞）；客户端都认（`lib/portraits.ts` 的 `splitMoodTag` / `moodKey`），标签不管在哪都从文字里去掉，认不出的才用 `neutral`。（Weiqi 测试时立绘一直不变，就是因为以前只认开头的标准写法。）
- 第 4 批完成了界面：列表、跳转、立绘（默认立绘包，离线显示 `offline`）、位置切换。创建 bot、按回复切换情绪已在第二阶段做完。
- 语音输入（只留了接口，Weiqi 定的先不做识别）：输入框工具栏有麦克风按钮，现在是灰的，提示「语音输入以后上线」。接口在 `client/src/lib/voice.ts`（`SpeechInput`：`available`、`start(onText)`、`stop()`），现在装的是空实现；以后做识别（系统语音接口经 Rust，或模型服务）时换掉 `voiceInput`，按钮自动可用。

**AI 形象**

- 形象包 = 一组按情绪命名的图片，文件名就是情绪名（如 `happy.gif`；带统一前缀也行，如 `dafeiyu_happy.png`，程序会去掉前缀）。客户端自带一套默认立绘包（`client/src/assets/portraits/default`，WebP），没有自己形象包的 AI 都用它。支持 PNG / WebP / GIF / APNG，动图会动；列表等小地方只显示第一帧。名字统一，形象包才能通用；形象包可附加额外情绪。
- 标准情绪 16 种 + 状态 2 种。只有 `neutral` 必须有，缺的按右边的顺序找替代（再缺就用 `neutral`）：

  | 名字 | 含义 | 缺了用 |
  | --- | --- | --- |
  | `neutral` | 普通（必需） | — |
  | `happy` | 高兴 | neutral |
  | `laugh` | 大笑 | happy |
  | `smug` | 得意 | happy |
  | `shy` | 害羞 | neutral |
  | `love` | 喜欢 | shy |
  | `sad` | 伤心 | neutral |
  | `cry` | 哭 | sad |
  | `worried` | 担心 | sad |
  | `scared` | 害怕 | surprised |
  | `angry` | 生气 | neutral |
  | `surprised` | 惊讶 | neutral |
  | `thinking` | 思考 | neutral |
  | `confused` | 疑惑 | thinking |
  | `speechless` | 无语 | confused |
  | `sleepy` | 困 | neutral |
  | `typing` | 状态：正在回复 | thinking |
  | `offline` | 状态：主人离线，AI 回不了话 | `neutral` 变灰 |

- 素材建议：正方形 512×512（不小于 256），透明背景，每张不超过 3 MB；同一套里人物大小、位置一致（半身，脸在中上部），切换时才不跳。
- 生图工具抠出来的图边上常有白点、白边：用 `scripts/portraits/clean_pack.py` 处理后再放进形象包。它只改人物外轮廓 3 像素以内（去零散白点、去半透明白边、线稿外圈的灰白晕染换成线稿颜色），里面的像素一个不动，输出无损 WebP。
- **Live2D（计划，难度高，排在 AI 功能之后）**：形象包可以带一个 Live2D 模型代替静态图片，情绪名对应模型的表情 / 动作，`typing` 用说话动作，`offline` 用睡觉或变灰。要解决的事：Cubism SDK 的许可（商用和分发条款要先看清楚）、网页端渲染（WebGL，体积和性能）、模型文件进工坊审核、和静态立绘同一套位置 / 收起 / 羽化效果。先做调研和一个能跑的样例，再定格式。
  - 调研记录（2026-10）：AI VTuber 项目 ZerolanLiveRobot 用的是 Python 的 live2d-py + OpenGL（桌面窗口，自动呼吸、眨眼、说话时动嘴），我们的界面是网页（Tauri），对应的是 Cubism Web SDK 或在它上面封装的 pixi-live2d-display（支持 Cubism 2.1 / 4 模型，Cubism 5 是否支持没查到）。说话动嘴可以按 TTS 音量或按「正在输入」做简单张合。
  - 许可：Live2D 官方说个人和年销售额 1000 万日元以下的小规模事业者免签发布许可、免费（「可扩展应用」除外，AM 能加载别人做的模型，可能算这一类，要发布前问清楚）；Cubism Core 不能随便再分发，具体按官网 SDK Release License。发布前一个月要办完许可。
- 回复带情绪：系统提示要求模型在回复开头输出 `[mood:xxx]`（xxx 为上表情绪名，不含两个状态），运行的客户端解析后去掉标签，情绪放进消息的 `mood` 字段发出（只有 ai / bot 账号的消息会保留这个字段），所以所有人看到的立绘都会跟着变；解析失败用 `neutral`。等待回复时显示 `typing`，AI 离线时显示 `offline`。不依赖任何一家的特殊功能。
- 形象包可上传工坊，审核注意版权（直接使用他人角色原图的不予通过）。
- 自己的 AI 用自己的形象包（已做）：AI 设置 → 资料 →「立绘（形象包）」。「导入一组图片」按文件名认情绪（规则同上，认不出的跳过并提示），也可以点格子一张张换、去掉；必须有 `neutral` 才能保存，「换回默认」清空。每种情绪一张图（最多 24 个），图片必须是主人自己上传的。服务器存在 `portrait_packs`（AI、情绪、图片），改动时更新 `users.portraits_at`（`User.portraits_at`），客户端按这个版本号缓存，看别人的 AI 时也 10 分钟重新读一次。所有人都能读（`GET /api/v1/users/{id}/portraits`），图片对所有人可见，媒体清理会保留它们。没有自己的包、或包里没有 `neutral` 时用默认包；缺的情绪按上表退回（`lib/portraits.ts` 的 `ownPack` / `resolveMood`，有单测）。

**人格设定**

- 一个人格包含：名字、简介、系统提示、示例对话、开场白、推荐服务商与模型、参数（温度等），可选绑定形象包。
- 内置几个默认人格，用户可自建；自建人格可上传工坊，上传内容即上述全部字段。下载者用自己的 key 调用；没有推荐的服务商时提示改用其他模型。
- 人格也可用于拉进群的 AI。审核重点：诱导点外链、借人格绕过服务商审核。

**私人 AI 进群**

- 是 ai 账号，调用发生在主人客户端，主人在线才回话。
- 离线期间被 @ 的问题，上线后按配置补回（最近 N 小时、最多 N 条），回复引用原问题并标明"离线期间的提问"。（已做：AI 上线 4 秒后看每个会话里它最后一次说话之后的消息，频道和共享聊天挑真人叫过它的，私信里挑最后一条，按时间从新到旧最多回 N 条，频道里引用原消息；设置 → 频道与作息，默认最近 12 小时、最多 5 条。）
- 入口两个：在 AI 栏里把自己的 bot 邀请进某个群；在群里点 bot 头像"添加到 AI 栏"（别人的 bot 进自己的 AI 栏 = 申请共用，见下）。
- 频道里除了"邀请成员"，还有"添加 bot"按钮，只能添加自己的 bot（服务器校验主人）。（已做：频道顶栏的机器人按钮，列出我自己还不在这个频道里的 AI，点一下拉进来；私密频道要审批的照常先申请。共享聊天里没有这个按钮。）

**共享 AI**

- 可以和服务器里的其他人共用一个 AI：在 AI 栏里一起跟它聊，聊天记录和记忆共享。必须经 bot 主人同意，主人可随时移除成员。
- 已做的样子：共享聊天是一个属于这个 AI 的私密频道（`conversations.ai_id`，`Conversation.ai_id`），主人在 AI 设置 →「频道与作息」里点「开一个共享聊天」建（`POST /api/v1/ai/{id}/room`，名字默认「X和大家」），用普通的「邀请成员」拉人、移除人。它出现在 AI 栏（不在频道页），列表里写「共享聊天 · N 人」，顶上有立绘。AI 在这里和普通频道一样按接话规则发言，也会记住每个人说过的事。主人以外的人每人每天最多 N 条（默认 50，0 = 不限），超过时 AI 发一句固定的话（不花模型额度）。
- 申请共用（已做）：别人在这个 AI 的个人主页上点「申请和它聊」（只有人类账号、不是主人才有；已经在它的共享聊天里就变成「去共享聊天」）。服务器记下申请（`ai_share_requests`，重复申请只算一条），推给主人（`ai_share_request`），主人那边弹提示、AI 栏里它那一行显示「N 个申请」。主人在 AI 设置 →「频道与作息」→「共享聊天」里同意或拒绝：同意就把人拉进它的共享聊天，没有就先建一个；拒绝就删掉申请。
- key 只在主人设备上，所以别人的消息由主人的客户端代为调用、用主人的额度，主人在线才回复（和群里的私人 AI 一样）。主人可设每人每天的条数上限。
- 共享会话的记录和记忆存在服务器上（一种特殊会话，成员 = 主人 + 被批准的人），换设备不丢。

**操作电脑（Windows，第 2 批：2a、2b、游戏接口已完成）**

- Windows 客户端带一套让 AI 操作电脑的工具（agent 循环：模型调用工具 → 客户端执行 → 结果交回模型，循环到完成，每次最多多少步写在设置里）。
- 2a（已完成）：
  - 三种接口的工具调用（OpenAI 兼容的 function calling、Claude 的 tool_use、Gemini 的 functionCall），流式里拼出工具参数（`lib/ai/providers.ts`，有单测）。
  - 工具（`lib/ai/agent.ts` 定义和权限分类，`lib/ai/tools.ts` 执行，Rust 在 `src-tauri/src/agent.rs`）：看文件夹 / 读文件 / 写文件 / 移到回收站（只在工作目录里，Rust 里解析 `..` 和链接后再检查一遍）、运行 PowerShell 命令（起始目录是第一个工作目录，有超时，输出用 UTF-8）、打开网址和文件、读写剪贴板、截屏（主屏，缩到 1280 宽，只有打开「模型能看图」才提供）、鼠标和键盘（坐标按截图换算）、等几秒。
  - 权限：每个 AI 设置里的「电脑」页。总开关、工作目录、每类各「允许 / 问我 / 不行」（2b 加了 3 类，共 11 类；旧设置里没有的类用默认值）；默认读写文件、打开、剪贴板、截屏、键鼠允许，删除和运行命令问我（Weiqi：尽量高权限）。把有风险的两类调成允许、或「谁能和它聊」是所有人时给警告，不限制。
  - 问我：运行它的设备上弹窗（是谁让它做的、要做什么），允许这一次 / 以后都允许 / 不允许，2 分钟没回答当不允许。
  - 让鼠标：每次动鼠标键盘前看你最近有没有动过（Windows 的 GetLastInputInfo，扣掉它自己的输入），你动了就等你停手 N 秒（设置里改，默认 3）再继续。

**频道和作息**（Weiqi 测试反馈，2026-11 完成）

- 进频道：用普通的「邀请成员」，或者 AI 设置 →「频道与作息」里列出主人在的频道，开关一下就拉进去（私密频道要审批时先申请）。拿出来：同一个开关（`DELETE /api/v1/ai/{id}/channels/{conv}`，只有主人能用）。
- @：输入框打「@」弹出频道成员（名字或用户名搜索，↑↓ 选，回车 / Tab 确定，Esc 关），发出的文字消息带 `mentions`；消息里被 @ 的名字高亮。AI 被 @、或者消息里出现它的名字（两个字以上），就算在叫它。
- 什么时候说话（`lib/ai/social.ts` 的 `decide`，纯函数有单测）：
  - 被叫到：1–2 秒后一定回（只受「每小时最多几句」限制）。
  - 「只在被 @ 或叫名字时说话」模式：其他时候不说。
  - 「会自己接话」模式（默认）：频道和共享聊天都先旁听。真人发来讨论内容时，有 0–30% 的机会考虑接话（默认 15%，由「话多少」调节）。纯表情和简短附和通常跳过，不主动接其他 AI 的话。等 5–12 秒，期间或生成回复时有新消息就放弃旧的插话。冷却期跳过，已有每小时上限和 AI 连续发言上限仍生效。
  - 模型只在能回答未解决的问题、提供具体的新信息或观点、纠正有影响的错误时参与；否则输出 `[skip]`。旁听时也照常整理记忆。
- 频道里的上下文：消息带「名字：」前缀，系统提示里列出频道成员（标出谁是 AI）。被叫到时提示「有人在叫你」。它的回复里写了「@某人」会自动带上 `mentions`，所以 AI 之间也能互相叫。
- 频道里能不能用「操作电脑」的工具：主人说话时可以；别人说话时要「谁能和它聊」是所有人。

## 10. Bot（第二阶段）

- 管理放在 AI 那一栏里（Weiqi 定的）：自己的 bot / AI 的主页、资料、在哪些频道、触发规则等都在那里设置，不放到账号设置。bot / AI 是单独的账号，不占主人的设备名额。

## 11. 表情包（第三阶段；个人表情、批量导入、公共表情库已提前做）

**我的表情**（第一步，Weiqi 测试反馈）：输入框旁的「表情包」按钮弹出表情面板，按标签搜，点一下发出（就是一条图片消息，带上 `ImageMsg.sticker_tags`——表情的前 10 个标签，聊天里显示成没有边框的小图）。「我的表情」里可以一次选很多张图批量导入，导入后自动切到「没标签的」，挨个填标签（回车或空格分开，每个 20 字）。「自动识别标签」按钮已经放好但不能点，等识别做好再开。AI 收到表情时看到的是「[发了一个表情：开心、狗头]」，不看图。没填标签的表情发出去就是普通图片。每人最多 `limits.max_stickers` 个（默认 1000）。

**公共表情库**（2026-11-01，Weiqi：「每个人添加的表情自动同步到公共库里」，规则由 Claude 定）

- **进库的规则**：加进自己收藏的表情默认公开，进服务器的公共库（`stickers.default_public`，管理面板能改）。每张都能改成「不公开」（管理里图左上角的小地球 / 小锁），批量导入时可以整批选「这批不公开」。聊天里发的普通图片不会自动进库；右键图片「加到我的表情」才算，频道和私信里的图都一样按默认公开（Weiqi 2026-11-01：表情包无所谓隐私，只是给一个可以不公开的选项）。
- **同一张图只有一份**：先比文件 SHA-256；不一样再比 256 位感知哈希（DCT pHash：缩到 32×32 灰度，取最低的 16×16 个频率，大于中位数记 1，`media.PHash256`）。相差不超过 `stickers.dedupe_distance`（默认 10，0 = 只合并完全相同的文件）、都是动图或都是静图、长宽比差不到 5% 才算同一张。测过：重新保存 / 改尺寸的同一张图相差 ≤ 4，同一张图下面字不一样的 ≥ 36，不同的图 ≥ 90。几乎没有对比度的图（标准差 < 8）不算哈希，只认相同文件。合并到最早进库的那张，显示它的上传者；以后传的人收藏里看到的也是库里那张。合并的文件 SHA-256 记在 `sticker_library_files`，下次直接认出来。动图只比第一帧。
- **标签大家一起补**：公开的表情只有一套标签，每条记着是谁加的（`sticker_library_tags`，一人一个标签一行）。谁都能加，每张最多 20 个不同的标签（`sticker_tags_full`）；只能去掉自己加的，站点管理员能去掉任何的。显示和发出去时按加的人数排，人多的在前。不公开的表情只有自己的标签（最多 10 个）。
- **改成不公开**：只断开自己；带着现在看到的标签变成自己的。库里这张没有别人收藏了就从库里拿掉（不是删除，没有证据要留）；有别人收藏的留在库里。删掉自己的表情也一样：没人收藏了就从库里拿掉。
- **已经有的表情**：升级后服务器启动时按同样规则全部进库（最早导入的优先成为库里那张）。「我的表情」顶上提示一次「你的表情现在默认公开」。库关掉时（`stickers.library = false`）加的公开表情也是这样，等库打开再补进去。
- **表情面板**分「我的」和「大家的」两栏。「大家的」：按标签搜（每个词都要是某个标签的一部分）、热门（收藏的人多的在前）/ 最新，往下「加载更多」；点一下直接发（不用先收藏），☆ 收藏，右键「补标签」能看到最早上传的人和收藏人数。
- **管理员**：管理面板「表情库」页（`admin/stickers.go`）：浏览、搜索、按状态看（公开的 / 已隐藏 / 已删除）。隐藏：「大家的」里不再出现，已经收藏的人还能用。删除：所有人的收藏里都去掉（不公开的同一张图也去掉），图片作为证据留在库里（面板「已删除」里能看），`retention.evidence_days` 天后清除；可以同时拉黑这张图（进图片黑名单，以后传不上来）。已经发出去的消息不受影响，要删按删除消息的流程。删标签、隐藏、删除都写操作记录。
- **跨服务器**：我在一个服务器上有的表情，客户端在后台慢慢复制到我的其他服务器（见第 7 节「资料同步」）。
- **代码**：服务器 `server/internal/sticker`（`sticker.go` 收藏，`library.go` 库和管理，`match.go` 判断同一张图和合并标签，纯函数有单测），表 `sticker_library`、`sticker_library_files`、`sticker_library_tags`，`stickers.library_id / is_private`。客户端 `lib/stickers.ts`、`app/Stickers.tsx`、`lib/stickerSync.ts`（复制）+ `lib/stickerCopy.ts`（纯函数有单测）。

- **别人没装的主页组件也要看得到**：
  1. 布局里记下工坊 ID、版本、组件包 SHA-256。
  2. 主人把工坊组件放上主页时，客户端顺手把组件包传到当前服务器（按 SHA-256 存，同一个包只存一份）。访客从这个服务器下载，不用连 GitHub。
  3. 访客端验工坊签名和 SHA-256，对得上才在沙盒里运行；只是临时缓存，不算安装。组件角上标「工坊组件」，旁边有「安装」。
  4. 主人保存时客户端给每个工坊组件截一张图一起存（`snapshot_media_id`）。侧载（未审核）的、被下架的、验签失败的组件，访客只看到截图，标「未审核，只显示截图」或「已下架」——不在别人设备上自动运行没审核过的代码。

## 14. 规模化预留

1. 按时间递增的消息 ID。
2. 会话内递增 seq，同步量只和离线时长有关。
3. 存储层隔离（`store` 包），同一套方法支持 SQLite 和 PostgreSQL。
4. 连接层（gateway）与业务层分开，模块经 `push.Pusher` 推送。
5. 媒体访问统一走 media 模块，以后切换到对象存储 + CDN 只改这一处。

**带宽参考（5 Mbps 中转 ≈ 每秒 0.6 MB）**：文字几乎不占带宽；10 人以内随便用；50 人活跃群在做好缩略图、表情缓存、动图不自动播放、文件限大小后，10–20 Mbps 比较宽裕。家里宽带上行也是上限。

## 15. 合规备忘

> 不是法律意见，正式对外前请律师过一遍。

- 法规对"上线"本身就有要求，没有"多少人以下不用管"的人数门槛。例如《具有舆论属性或社会动员能力的互联网信息服务安全评估规定》：开办聊天室、通讯群组、论坛等服务上线时，或用户规模显著增加时，应自行开展安全评估。
- 实际上被关注的程度，主要看是否面向**不特定公众**：开放注册（不需邀请码）、应用商店上架或公开下载链接、陌生人可见的公开广场、可被搜索引擎收录、收费。出现这些之前，应补齐：
  - 备案（服务器在大陆且使用域名）；
  - 后台实名、前台自愿（手机号验证）；
  - 网络日志留存不少于 6 个月；
  - 违法信息处置、拉黑、保存记录并向主管部门报告的流程；
  - 安全评估。
- 刑事风险最重的是拒不履行信息网络安全管理义务罪，前提是被监管部门责令改正后仍拒不改正。被要求整改时必须配合。
- 管理员删除保留证据（第 6 节）正是为了不造成"证据灭失"。
- 自建模式下，各服务器的合规由搭建者负责；官方需负责的是创意工坊（公开分发的用户内容）。
